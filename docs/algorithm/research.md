# 算法调研与选型依据

> 本文是课程要求的「算法说明（推导、复杂度、参数）」入口。具体公式与实现见
> [algorithm.md](algorithm.md)；历史调研全文保留在 `docs/research/`，只作追溯。

## 1. 要解决的问题

MindMeter 不做诊断、不设总分、没有常模。算法层要回答的是：

1. 每个维度用哪些**原始指标**（正确数、虚报数、平均反应时等）折算成 0–100 的参考分；
2. 同一份原始数据必须得到**可复现**的分数（前端显示 = 服务端入库 = 趋势 = Agent facts）；
3. 缺数据时返回 `null`（未测），绝不按 0 分计算。

## 2. 候选方案与取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 标准化常模（z 分数/百分位） | **不采用** | 没有信效度证据与人群样本，伪造常模违反产品定位（ADR-0002） |
| 机器学习模型打分 | 不采用 | 缺少标注数据，不可解释，无法向用户说明「为什么是这个分」 |
| 规则化指标折算（scoring-v3） | **采用** | 可解释、可复现、可单测；每个维度只依赖本任务原始指标 |
| 前端独立计分 | 不采用 | 分数必须唯一权威；前端只做即时预览，最终以服务端为准 |

## 3. 计分口径

- 版本：`scoring-v3.2`（`code/core_engine/scoring/`）；
- 维度：`vc` 言语理解、`vf` 言语流畅性、`nc` 数字运算、`ps` 知觉速度、`ir` 归纳推理、`sv` 空间视觉化、`am` 联想记忆、`ni` 自然探索；
- 输出：每维 0–100 的**参考分**，缺失返回 `null`；不输出总分、百分位、误差范围；
- 复杂度：每维 O(n)（n = 该维度题目数），统计量为中位数/比率，无迭代优化。

## 4. 一致性保障

| 约束 | 保障 |
| --- | --- |
| 服务端唯一权威 | `code/core_engine/scoring` 只依赖标准库，`backend/app/scoring` 只是兼容 shim |
| 前后端不漂移 | `tests/backend/test_scoring_golden.py` 钉住金标准；`scripts/test_scoring.js` 钉同一组数字 |
| 历史可追溯 | 算法变更只通过 migration 与版本号（`SCORING_VERSION`）推进 |
