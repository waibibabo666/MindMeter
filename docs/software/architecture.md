## 0. 摘要

| 决策 | 结论 | 理由 |
| --- | --- | --- |
| 前端 | 原生 HTML/CSS/JS，无构建 | 6 个屏、无路由；计时比渲染重要 |
| 计分 | 独立纯函数 + `node:test` | 可复现、可单测、与 UI 解耦 |
| 存储 | `localStorage`，存试次级数据 | 无账号、不出设备；行为叙事需要试次 |
| 部署 | GitHub Pages | 零成本、可回滚、断网可演示 |
| AI | 规则定结论，模型只表达 | 结论必须可复现；模型只管措辞 |
| AI 接入 | 默认模板，网关可选 | 模板即可出完整报告，网关是增强 |

## 二、技术选型

### 2.1 前端

| 维度 | 原生 JS | Vite+React | Vite+Vue | Next.js | 小程序 |
| --- | --- | --- | --- | --- | --- |
| 学习成本 | 低 | 中 | 中 | 高 | 中高 |
| 构建 | 无 | 需要 | 需要 | 需要运行时 | 需要工具 |
| 体积 | 0 | ~140KB | ~100KB | 更大 | 平台限制 |
| 计时适配 | 好 | 一般 | 一般 | 一般 | 一般 |
| 演示风险 | 低 | 中 | 中 | 高 | 高 |

**结论：选原生 JS。** 三条理由：

1. 核心是毫秒级计时，不是渲染。React 的状态更新会引入不可控延迟，测量点更难界定。
2. 6 个屏、无路由、无跨页状态，框架解决的问题不在这里。
3. 静态文件可双击打开，答辩现场最稳。

例外：W4 若页面复用不可维护，可局部引入 Vite 打包，不换框架。

### 2.2 存储

| 方案 | 结论 | 理由 |
| --- | --- | --- |
| `localStorage` | ✅ | 同步、简单，5MB 够存数十次测评 |
| IndexedDB | ❌ | 异步复杂，需求未到 |
| 后端库 | ❌ | 要账号，与"不收集身份信息"冲突 |

必须存**试次级数据**，非仅聚合分：行为叙事依赖它。一次测评约几百条、几十 KB。

### 2.3 部署

GitHub Pages；每周演示版本打 tag；回滚即切 tag；断网时本地文件 + 录屏兜底。

## 三、架构

### 3.1 模块

| 模块 | 职责 | 红线 |
| --- | --- | --- |
| `pages` | 首页、同意、说明、报告、历史 | 不写计分 |
| `games` | 试次控制与指标采集 | 不判定分数 |
| `core_engine` | 计分、分档、版本 | 不碰 DOM、不发请求 |
| `ai` | 叙事、追问、计划 | 不改分数、不改结论集合 |
| `templates` | 文案与建议库 | 不含逻辑 |
| `storage` | 本地读写与异常 | 不上传 |

### 3.2 数据流

```text
游戏 → 原始指标 → 计分 → 分档与 facts
                        ↓
              AI 开关（默认关）
              ↓ 开            ↓ 关
        模型 → 校验        模板渲染
              ↓ 失败          ↓
              └──→ 模板 ←─────┘
                        ↓
                  报告 / 历史
```

### 3.3 目录

```text
code/
├─ frontend/
│  ├─ index.html
│  └─ src/{pages,games,components,styles}/
├─ core_engine/
│  ├─ src/{scoring.js,config.js}
│  └─ test/
└─ ai/
   ├─ prompt.js
   ├─ validate.js
   └─ templates.js
```

## 四、数据模型

```json
{
  "id": "s_20261024_1",
  "startedAt": "2026-10-24T20:00:00+08:00",
  "finishedAt": "2026-10-24T20:13:20+08:00",
  "tier": "standard",
  "version": "scoring-v2",
  "scores": { "wm": 45, "inh": 72, "spd": 68, "mem": 61 },
  "results": { "wm": { "maxSpan": 4, "accuracy": 0.63 } },
  "trials": { "wm": [{ "i": 1, "correct": true, "span": 3 }] }
}
```

| 键 | 用途 | 生命周期 |
| --- | --- | --- |
| `mindmeter.sessions.v1` | 全部测评记录 | 用户清除 |
| `mindmeter.draft.v1` | 进行中的测评 | 完成或退出 |
| `mindmeter.settings.v1` | AI 开关、偏好 | 用户清除 |

规则：只存测评数据；不存姓名、手机、设备号；版本号写入每条记录。

## 五、模块契约

| 函数 | 输入 | 输出 | 失败 |
| --- | --- | --- | --- |
| `scoreSession(results)` | 原始指标 | `{ scores, overall }` | 缺数据返回 `null` 维度 |
| `buildFacts(session)` | session | facts JSON | 数据不足标记 `confidence: low` |
| `readSessions()` | — | 数组 | 解析失败返回空数组 |
| `appendSession(s)` | session | `true/false` | 存储失败返回 false |
| `generate(facts)` | facts | 文本 JSON | 超时/异常抛错，由上层降级 |
| `validate(text, facts)` | 文本 + facts | `{ ok, reason }` | 任何异常视为不通过 |

## 六、AI 方案

### 6.1 候选

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A 纯模板 | 文案套变量 | 保留作兜底 |
| B 单次生成 | 分数直接丢模型 | 不可控，弃 |
| **C 规则 + 表达** | 结论由规则产出，模型改写 | ✅ 采用 |
| D 多 Agent | 规划→分维→审稿→汇总 | 6 周做不完 |
| E 对话教练 | 多轮 + 记忆 + 工具 | 降为 P1 追问 |

### 6.2 为什么是 C

1. **可复现**：分数、分档、建议集合全由代码产出。
2. **可追溯**：每条建议带 ID，能映射回维度。
3. **可解释**：答辩能指出"这条建议为什么出现"。
4. **可降级**：模型挂掉，A 方案就是完整产品。

### 6.3 两种形态

| 形态 | 后端 | 适用 | 特点 |
| --- | --- | --- | --- |
| A 纯静态 | 无 | 快测、标准档、断网 | 运行时零请求 |
| B 网关 | 单函数 | 深度档、追问 | key 不进前端，只转发 |

先做 A；W4 视进度决定是否上 B。

### 6.4 质量控制

- 五项校验：结构合法、建议 ID 在池内、数字来自 facts、禁用词 0、长度达标；
- 生成后自检一次；
- 强制模板五种：无可信结论、数据不足、间隔过短、危机词、超时；
- 记录版本、模型、是否降级。

## 十、技术风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 移动端点击延迟 | 污染反应时 | `touch-action: manipulation`，统一 `pointerdown` |
| 后台节流 | 试次错乱 | 监听 `visibilitychange`，切回重置 |
| 存储不可用 | 静默丢数据 | `try/catch` + 明确提示 |
| 模型幻觉 | 编造数字 | 数字比对 + ID 校验 + 模板兜底 |
| 无常模 | 无法给百分位 | 只做自身对比 |
| 断网 | 页面打不开 | 本地版本 + 录屏 |
