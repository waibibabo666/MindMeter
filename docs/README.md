# MindMeter 文档中心

本目录是项目文档的唯一事实来源（Single Source of Truth）。代码之外的决策、需求、计划与复盘均在此维护。

## 1. 文档状态

| 状态 | 含义 | 允许的下一步 |
| --- | --- | --- |
| 草稿（Draft） | 作者编写中，内容不完整 | 内部评审 |
| 评审中（In Review） | 已提交评审，等待意见 | 批准 / 退回修改 |
| 已批准（Approved） | 决策人签字，可作为执行依据 | 变更需走变更流程 |
| 已归档（Archived） | 被新版本替代，仅保留追溯 | 只读 |

文档信息表中的「状态」必须与本节定义一致。v0.1 全部文档默认为**草稿/评审中**，团队评审会后改为**已批准**并补齐签字人。

## 2. 编号规则

| 前缀 | 用途 | 示例 |
| --- | --- | --- |
| `MM-REQ-xxx` | 需求类文档 | MM-REQ-001 |
| `MM-PM-xxx` | 项目管理类文档 | MM-PM-001 |
| `MM-DES-xxx` | 设计类文档 | MM-DES-001 |
| `FR-xxx` | 功能需求 | FR-204 |
| `NFR-xxx` | 非功能需求 | NFR-PERF-001 |
| `BR-xxx` | 业务规则 | BR-003 |
| `R-xx` | 风险 | R-01 |
| `D-xx` | 待决策事项 | D-01 |
| `A-xx` | 假设 | A-01 |

规则：

- 编号一经分配**不复用、不回收**；废弃需求标记「已废弃」并保留编号。
- 功能需求按模块分段：`1xx` 账号、`2xx` 测评、`3xx` 计分报告、`4xx` 追踪成长、`5xx` 分享隐私、`6xx` 运营后台、`7xx` 通知、`8xx` 数据权利。
- 非功能需求按质量属性分段：`PERF`、`REL`、`SEC`、`PRIV`、`USA`、`COMPAT`、`MAINT`、`OBS`、`DATA`、`L10N`、`COST`、`LEGAL`。

## 3. 文档变更流程

1. **提出**：Issue 标注 `docs`，说明改什么、为什么、影响哪些文档。
2. **编辑**：创建 `docs/<slug>` 分支，更新正文、版本号、修订记录与待决策表。
3. **评审**：至少 1 名相关角色评审；涉及范围/计分/隐私的需对应负责人批准。
4. **合并**：Squash merge 到 `main`，同步更新 [README](../README.md) 与本文档地图（如新增文件）。
5. **发布**：里程碑节点打标签，归档旧版本。

版本号规则：`v0.<minor>` 用于草案迭代；批准后为 `v1.0`；重大修订升 `major`。

## 4. 评审节奏

| 评审 | 频率 | 参与人 | 产出 |
| --- | --- | --- | --- |
| 需求评审 | 每个迭代开始前 | 产品、技术、算法、设计、QA | 需求基线、待办 |
| 文档走查 | 每两周 | 文档负责人 | 失效链接、过期内容清单 |
| 里程碑评审 | 每个里程碑 | 全体 + 决策人 | 放行/不放过结论 |
| 复盘 | 每个里程碑后 | 全体 | 改进行动项 |

## 5. 写作约定

- 语言：简体中文；术语首次出现给出英文与解释。
- 标题层级从 `#` 开始，不跳级；表格前后留空行。
- 相对链接使用仓库内路径，不使用本机绝对路径。
- 数字与结论必须可追溯：给出处、口径、时间；未经验证的写「假设」并登记。
- 避免临床化表述：使用「测评结果」「倾向」「相关」，不使用「诊断」「确诊」「治愈」。
