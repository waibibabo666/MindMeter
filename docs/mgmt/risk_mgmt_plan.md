## 二、目的与原则

L2 的最大风险不是“技术太难”，而是**范围太大、Agent 质量不稳、隐私/Key 出事、测评与后端同时铺开**。本计划只跟踪会影响 M0–M3 交付的风险。

- 阶段制；每个阶段有明确验收；
- 先纵向切片，不一次全铺；
- 高风险优先砍范围，不优先加班；
- Agent/Key/隐私问题立即升级；
- 新增能力必须有校验、降级、评测。

## 四、三个重点风险

### R-01 范围过大

- **预警**：M1 还在补 8 项/三档；Agent/RAG/记忆任一未跑通；开始做练习/分享。
- **预防**：M1 固定“账号 + 标准 4 项 + 服务端计分 + 对话 + 记忆 + RAG + 趋势”；M2 才补 8 项。
- **应急**：砍深度档/练习；保纵向切片；不偷偷回退 L1。

### R-02 Agent 幻觉

- **预警**：回答出现 facts 外数字；建议不在池；越界词；引用缺失。
- **预防**：五条校验；30 条评测；模板兜底；不开放全网搜索。
- **应急**：停用模型版，只走模板；修复后重跑评测。

### R-04 Key 泄露

- **预警**：日志/异常/导出出现 Key；主密钥进仓库；前端 bundle 有 Key。
- **预防**：加密存库；日志脱敏；CI secret 扫描；代码评审。
- **应急**：轮换主密钥；通知受影响用户；保留审计记录。

## 五、阶段门禁

| 阶段 | 必须满足 |
| --- | --- |
| M0 | 数据模型/API/隐私/知识库 schema/评测集定稿 |
| M1 | 注册→标准 4 项→报告→对话→记忆→复测→趋势跑通；30 条评测通过 |
| M2 | 8 项/三档/ASR 跑通；无总分/常模；删除/导出可用 |
| M3 | 备份恢复演练；安全扫描；告警；成本可接受 |

## 六、监控与更新

- 每周过一遍登记册；
- 每周演示后更新状态（开放/缓解/关闭）；
- 立即升级：隐私/Key 事件、幻觉数字、越界回答、数据丢失、演示环境不可用。
