## 二、写法与用法

- 每条故事只描述一个用户在一次使用中能感知到的一个完整价值；
- 故事正文用「角色 / 功能 / 价值」三段式；验收条件用 Gherkin，条件是**可判定**的；
- 数字来自功能需求第六节与非功能需求，不另造一套；
- 一条故事只有在全部验收条件通过时才算完成；
- 本文的估算是“故事层”估算，8 个任务本身的实现工时另计。

## 五、故事详情

### US-01 首页看清 8 项能力和三档（P0 · 1 人日）

**角色**：作为一名第一次听说 MindMeter 的大学生
**功能**：我想在打开页面后一眼看清它测哪 8 项、三档各要多久、是不是医疗诊断
**价值**：从而判断值不值得投入 5–28 分钟

```gherkin
场景: 首次打开首页
  Given 用户第一次打开 MindMeter，且本地没有任何测评记录
  When 页面在 4G 网络下加载完成
  Then 应在 3 秒内显示 8 项能力名称与“快测 5 / 标准 13 / 深度 28 分钟”
  And 应显示“本产品不是医疗器械，不提供临床诊断”
  And 应显示“不设总分、没有常模、不做人群比较”
  And 在 360px 宽的屏幕上不应出现横向滚动，“开始测评”无需滚动即可见
  And 文案中不出现“智商”“诊断”“异常”“超过 X% 同龄人”等词

场景: 选择档位
  Given 用户停留在首页
  When 用户点击“开始测评”
  Then 应进入档位选择页，而不是直接进入任务
  And 档位页应分别列出快测 2 项、标准 4 项、深度 8 项及预计时长
```

### US-02 两项确认后才开始（P0 · 0.5 人日）

**角色**：作为一名不想注册账号、在意隐私的用户
**功能**：我想在开始前确认数据只存在本机、并且随时可以删除
**价值**：从而放心把自己的表现交给这个页面

```gherkin
场景: 两项确认缺一不可
  Given 用户已进入知情同意页，两项勾选均未选中
  When 用户只勾选“我已满 18 岁”
  Then “开始测评”按钮应保持不可用
  And 页面应写明“数据仅保存在本机浏览器，可随时清除，清除后不可恢复”
  When 用户再勾选“我理解本产品非诊断用途”
  Then 按钮应变为可用

场景: 未满 18 岁
  Given 用户取消了“我已满 18 岁”的勾选
  When 用户尝试继续
  Then 页面应提示“本产品仅面向 18 岁及以上用户”并停留在同意页

场景: 不收集人口学信息
  Given 用户进入同意页
  Then 页面不应出现年龄、学历、学校、公司、手机号、姓名等输入框
```

### US-03 5 分钟完成快测（P0 · 2 人日）

**角色**：作为一名只有几分钟、想先看看的用户
**功能**：我想只做 2 项任务就拿到两项分数
**价值**：从而用最低时间成本判断要不要做标准/深度

```gherkin
场景: 快测只包含 2 项
  Given 用户选择了快测
  When 用户通过同意页
  Then 任务顺序应为“知觉速度 → 言语流畅性”
  And 顶部进度应显示“第 1 / 2 个任务”
  And 总时长目标为 5 分钟（允许 ±20%）

场景: 快测不显示未测维度
  Given 用户完成了快测的 2 项
  When 报告生成
  Then 应显示知觉速度、言语流畅性两项分数
  And 其余 6 项应显示“未测”，而不是 0 分
  And 不应显示总分/均分

场景: 浏览器不支持 ASR
  Given 用户使用不支持 Web Speech API 的浏览器
  When 用户打开档位页
  Then 快测应被禁用并提示“当前浏览器不支持 ASR，请选标准或深度”
  And 标准档仍可选择
```

### US-04 13 分钟完成标准档（P0 · 3 人日）

**角色**：作为一名愿意花十几分钟看四项的用户
**功能**：我想完成言语理解、知觉速度、空间视觉化、联想记忆四项
**价值**：从而拿到比快测更完整的结构

```gherkin
场景: 标准档任务顺序
  Given 用户选择了标准档
  When 用户通过同意页
  Then 任务顺序应为“言语理解 → 知觉速度 → 空间视觉化 → 联想记忆”
  And 顶部进度应显示“第 n / 4 个任务”
  And 每个任务开始前应有 1–2 次练习，练习不计分

场景: 标准档完成
  Given 用户完成 4 个任务
  When 第 4 个任务结束
  Then 报告应在 1 秒内展示
  And 应显示 4 项分数 + 4 项“未测”
  And 不应显示总分/均分
```

### US-05 28 分钟完成深度档（P1 · 4 人日）

**角色**：作为一名想看清完整 8 项结构的用户
**功能**：我想完成全部 8 项任务
**价值**：从而得到八维雷达图和跨维度解释

```gherkin
场景: 深度档任务顺序
  Given 用户选择了深度档
  When 用户通过同意页
  Then 任务顺序应为“言语理解 → 数字运算 → 归纳推理 → 知觉速度 → 空间视觉化 → 联想记忆 → 自然探索 → 言语流畅性”
  And 顶部进度应显示“第 n / 8 个任务”
  And 总时长目标为 28 分钟（允许 ±20%）

场景: 深度档中途退出
  Given 用户完成了 3 个任务，正在第 4 个任务
  When 用户点击“退出”
  Then 系统应二次确认
  And 确认后保留已完成任务到 draft，回到首页
```

### US-06 看到八维报告，没有总分（P0 · 2 人日）

**角色**：作为一名刚做完任务的用户
**功能**：我想看到 8 个维度的分数和雷达图
**价值**：从而知道自己的结构，而不是只拿到一个总分

```gherkin
场景: 八维数据齐全时生成报告
  Given 用户完成了深度档 8 个任务，且每个任务有效试次不低于 80%
  When 最后一个任务结束
  Then 系统应在 1 秒内展示报告页
  And 报告应包含八维雷达图和 8 个 0–100 的整数分数
  And 每个维度应有一句中性解释，不出现“很差”“很聪明”等评价
  And 页面应显式标注“课程演示参考分，非常模、非临床、无人群比较”
  And 页面不应出现总分、均分、智商、脑龄、百分位、误差范围

场景: 出现未测维度
  Given 某个任务因异常中断，有效试次不足 80%
  When 报告生成
  Then 该维度应显示“未测”，而不是 0 分
  And 雷达图该轴应留空
  And 不应静默用均值补齐

场景: 局限说明
  Given 用户打开报告
  Then 应看到“本期不测工作记忆、抑制控制、认知灵活性”
  And 应看到“样本少、无临床常模、受状态影响、练习效应”
```

### US-07 拿到 2–3 条针对弱项的建议（P0 · 1 人日）

**角色**：作为一名测完发现某项偏弱、想改善的用户
**功能**：我想拿到 2–3 条针对最低维度的具体动作
**价值**：从而知道下一步练什么，而不是看完分数就结束

```gherkin
场景: 按最低维度给建议
  Given 用户完成了标准档或深度档
  When 报告生成
  Then 建议区应给出 2–3 条建议，且全部取自最低的 1–2 个已测维度
  And 每条建议应为可执行动作
  And 文案不得出现“治疗”“提升智商”“改善注意力缺陷”等表述
  And 不得承诺“练两周就能提升”

场景: 文案集中维护
  Given 产品负责人修改了建议文案配置
  When 刷新报告页
  Then 新文案应生效，且不需要改动计分逻辑或页面结构代码
```

### US-08 对比两次测评的共同维度（P1 · 1.5 人日）

**角色**：作为一名隔了一周回来复测的用户
**功能**：我想看到这次和上次共同维度的分数变化
**价值**：从而判断自己的状态有没有变化，而不是只记住上次一个模糊的数

```gherkin
场景: 第二次测评后的对比
  Given 用户本地已有一条完成于 7 天前的测评记录
  When 用户完成第 2 次测评
  Then 报告页应显示两次都测过的维度的变化值（本次 − 上次）
  And 只比较共同维度，不比较总分
  And 应提示“复测间隔建议 7 天以上，变化不等于训练效果”

场景: 档位不同
  Given 用户第一次做快测，第二次做标准档
  When 打开对比
  Then 只比较“知觉速度”这一项共同维度
  And 不得把快测 2 项与标准 4 项强行凑成总分

场景: 立即复测
  Given 用户刚刚完成一次测评
  When 用户在 7 天内再次开始测评
  Then 系统应允许开始，但提示练习效应可能影响结果
  And 不得阻止用户继续
```

### US-09 刷新后从当前任务继续（P0 · 1.5 人日）

**角色**：作为一名中途被叫走、误关页面的用户
**功能**：我想刷新后保留已完成任务，从当前任务继续
**价值**：从而不用把已经做完的任务重做一遍

```gherkin
场景: 刷新后恢复进度
  Given 用户已完成 3 个任务，正处在第 4 个任务
  When 用户刷新页面
  Then 前 3 个任务的结果应被保留
  And 应从第 4 个任务的说明页重新开始
  And 已完成的 3 个任务不应被要求重做

场景: draft 过期
  Given draft 已超过 24 小时
  When 用户重新打开页面
  Then 应提示“上次进度已过期”，并允许重新开始
  And 不得把过期 draft 静默算进新测评
```

### US-10 一键清除全部数据（P0 · 0.5 人日）

**角色**：作为一名把设备借给别人的用户
**功能**：我想一次性删掉本机保存的全部记录、draft 和 API Key
**价值**：从而在分享设备前不留下自己的数据

```gherkin
场景: 清除本地记录
  Given 用户本地存有 3 条测评记录、1 份 draft、1 个 BYOK Key
  When 用户在设置页点击“清除全部数据”
  Then 系统应弹出二次确认，说明“清除后不可恢复”
  When 用户确认
  Then sessions/draft/settings（含 Key）/practice 应全部被删除
  And 历史页显示“暂无记录”
  And 再次打开页面时不应出现已删除的记录或 Key

场景: 存储写入失败
  Given 浏览器处于隐私模式或存储空间已满
  When 测评结束尝试写入记录
  Then 系统应提示“保存失败，本次结果不会被保留”
  And 不得显示“已保存”或假装写入成功
```

### US-11 用 ASR 完成言语流畅性（P0 · 2 人日）

**角色**：作为一名有麦克风的用户
**功能**：我想用 60 秒口头说出动物名，由页面自动转写计数
**价值**：从而完成言语流畅性任务，而不用手打字

```gherkin
场景: 正常录音
  Given 用户使用 Chrome/Edge，并已授权麦克风
  When 用户开始言语流畅性任务
  Then 应显示 60 秒倒计时和“正在聆听”
  And 只统计不重复、属于动物类别的词
  And 音频和转写文本不得写入 localStorage
  And 任务结束后应显示有效词数，不显示原始转写全文

场景: 麦克风被拒
  Given 用户拒绝麦克风或浏览器不支持 Web Speech API
  When 用户开始言语流畅性任务
  Then 应提示“当前浏览器/设备无法完成言语流畅性；快测不可用，建议标准档”
  And 不得提供键盘输入替代
  And 深度档该维度应显示“未测”
```

### US-12 用自己的 Key 开启 AI 解读（P1 · 2 人日）

**角色**：作为一名愿意自己提供模型 API 的用户
**功能**：我想在设置里填入自己的 endpoint/model/key，开启报告解读和追问
**价值**：从而在不把数据交给项目组服务器的前提下，得到更自然的解释

```gherkin
场景: 默认关闭
  Given 用户第一次打开设置页
  Then AI 应处于关闭状态
  And 报告页应显示模板解释，不发起任何网络请求

场景: 配置 BYOK
  Given 用户填写 endpoint、模型名和 API Key
  When 用户点击“保存并开启”
  Then Key 应只保存在本机 localStorage
  And 页面应提示“Key 会保存在本机，公用设备请勿使用”
  And 请求只包含维度分、建议 ID、复测差值、完成度
  And 请求不得包含姓名、手机号、年龄、学历、原始试次、ASR 文本

场景: AI 失败
  Given 用户已开启 AI，但模型超时/断网/返回越界内容
  When 报告页尝试生成解读
  Then 应在 8 秒内回退模板
  And 页面不得出现空白或报错
  And 分数和图表不受影响

场景: 关闭 AI
  Given 用户关闭 AI
  When 打开报告
  Then 报告应完整显示，只标注“当前为模板解释”
```

## 六、本期不做（已确认）

- 账号、登录、支付、B 端；
- 工作记忆、抑制控制、认知灵活性任务；
- 常模、百分位、误差范围、总分；
- 两周计划、理解度复盘、AI 自检、语音多模态；
- 8 款独立练习游戏：只保留心算、舒尔特、翻牌、快速分类 4 款，作为补充练习（P2）。
