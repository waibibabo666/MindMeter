# Agent 平台调研与我们的 AI 用法

## 一句话结论

平台解决的是"让 AI 编排很多工具"，我们只有 4 个本地小工具，用不上平台。但平台的设计思路值得借：我们自己做了一个"薄 Agent"，只负责把分数讲成人话。

---

## 一、平台通常能干什么

| 能力 | 说明 | 我们要不要 |
| --- | --- | --- |
| 接多家模型 | 换模型、按价格切换 | 不要，一个够用 |
| **调用工具** | 让 AI 去查数据、算东西 | **要** |
| **记住对话** | 记住刚才聊了什么 | **要一点**（3 轮） |
| 编排多步 | 自动规划一串步骤 | 不要，我们没那么多步骤 |
| 接知识库 | 让 AI 查文档 | 不要，建议是固定的 |
| **内容护栏** | 拦住不该说的话 | **要** |
| 监控与日志 | 记录每次调用 | 简单记一下 |

九项里，我们只要三项：**工具、记忆、护栏**。

## 二、四类平台，为什么都不选

| 类型 | 代表 | 为什么不选 |
| --- | --- | --- |
| 编排框架 | LangGraph、AutoGen | 学 3–5 天，能力严重过剩 |
| 低代码平台 | Dify、Coze | 要后台服务，和"纯静态、无账号"冲突 |
| 云托管 | Bedrock、Azure | 要联网、要付费、绑定云 |
| 前端库 | Vercel AI SDK | 唯一备选，只在演示时用 |

## 三、我们的 Agent 只做三件事

1. **报告解读**：把四个分数写成一段人话；
2. **快测分诊**：告诉你值不值得做完整版；
3. **追问回答**：回答"为什么我这项低"。

流程很简单：

```text
用户提问 / 测评结束
      ↓
规则判断意图（解释 / 无关 / 越界）
      ↓
查数据（分数、建议）      ← 最多调 2 次工具
      ↓
生成一段话
      ↓
过一遍护栏
      ↓
通过就展示；不通过就用模板
```

## 四、它能调用什么

| 工具 | 作用 | 能不能改数据 |
| --- | --- | --- |
| `scoreSession` | 把原始成绩算成分数 | 否 |
| `readLatestSession` | 读最近一次测评 | 否 |
| `lookupAdvice` | 从固定建议库里取建议 | 否 |
| `renderReport` | 把报告画到页面上 | 否 |

**四个工具全部只读**，所以不存在"AI 把数据改坏"这种事故。

## 五、它不能做什么

| 不能做 | 为什么 |
| --- | --- |
| 算分、改分 | 分数必须每次都一样，模型做不到 |
| 决定测哪些维度 | 这是效度问题，不是生成问题 |
| 诊断、说病 | 产品不是医疗器械，一句话越界就完了 |
| 自己编建议 | 建议必须来自固定库，编出来的没法核实 |
| 给"认知类型"贴标签 | 没有常模支撑，属于伪科学 |
| 参考聊天内容给人打分 | 对话不可比、可外包，换个模型结果就变 |

## 六、怎么保证不说错话

五条护栏：

- **禁用词**：治疗、诊断、正常、异常、提升智商、脑龄等，命中就拦；
- **只用给的数据**：回答里的数字必须是输入里有的，编的一律判失败；
- **建议只能改写**：不许新增条目；
- **200 字上限**；
- **结尾固定加声明**：非诊断、非常模，由程序追加，不交给模型写。

出事了怎么办：

| 情况 | 处理 |
| --- | --- |
| 超时 / 返回乱码 | 用模板文案 |
| 命中禁用词 | 重生成一次，还不行就模板 |
| 断网 | 不调用，直接模板 |
| 内容太长 | 截断，保留声明 |

一句话：**用户永远看不到报错，只看到降级后的内容。**

## 七、什么时候上线

| 阶段 | 做什么 |
| --- | --- |
| W4 | 报告解读（用提前写好的模板，不联网） |
| W5 | 追问回答 + 完整护栏 |
| W6 | 深度档的组合解释 |

顺序不能反：**先把模板版做稳，再接模型**。模板版本身就是一个完整产品，模型只是让话更像人说的。

## 八、怎么验收

1. 20 条人工评分，准确、有用、不说越界话，各 ≥ 4/5；
2. 禁用词 0 次；
3. 模型挂掉时页面显示模板，不报错；
4. **关掉 AI，报告照样完整**；
5. 同一份分数两次生成，结论一致。

第 4 条最重要——它证明 AI 是增强，不是依赖。

## 九、答辩一句话

> 我们调研了 Dify、Coze、LangGraph 和 OpenAI Agents SDK，它们解决的是多工具编排和知识库，而我们的工具只有四个本地纯函数；平台还要求后端和密钥，和"纯静态、数据不出设备"冲突。所以我们只借了它们的设计思路——工具调用、短对话记忆、内容护栏——自己做了一个约 200 行的薄 Agent。
