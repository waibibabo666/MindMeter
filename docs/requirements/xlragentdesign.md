> Agent 是产品核心，不是“报告下面的一个解读卡片”。它解释、追问、记住、看趋势；但**不做诊断、不做计划/打卡、不做情绪疏导**。

## 二、一句话

**测评产生 facts，知识库提供依据，记忆提供连续性，LangGraph 负责可控编排，模型负责把话说人话。**

## 三、Agent 做哪些事

| 场景 | 输入 | 输出 |
| --- | --- | --- |
| 报告解读 | 当前 facts（八维分数、原始指标、档位） | ≤150 字解读 + 边界声明 |
| 追问 | 用户问题 + facts + 记忆 + 知识块 | ≤200 字回答 + 引用 |
| 趋势解释 | 最近两次测评、共同维度差值、间隔 | ≤300 字变化说明，不判断进步/退步 |
| 记忆回看 | 画像、摘要、建议记录 | 情境化建议、避重 |
| 支持性回应 | 情绪困扰类表述 | 共情 + 求助渠道 + 明确不诊断（固定话术） |

**不做**：7 天计划/打卡、情绪支持治疗、诊断/用药、认知类型标签、AI 判分、AI 选维度、全网搜索、公开分享、跑代码/改文件（`off_task`）。

## 四、能力边界

| 可做 | 不可做 | 理由 |
| --- | --- | --- |
| 解释八维分数和原始指标 | 算分、改分、调权重 | 分数必须可复现 |
| 从知识库选建议并改写 | 自创新方法/疗效 | 无法核实、无法追溯 |
| 解释维度组合与趋势 | 判断“你进步了/退步了” | 没有常模/误差范围 |
| 引用用户目标、上次建议 | 引用已删除/未授权数据 | 隐私与信任 |
| 追问时反问澄清 | 回答医疗、用药、诊断 | 非医疗器械定位 |
| 趋势解释 | 承诺训练效果 | 没有信效度证据 |

**AI 出错时，错的只能是措辞，不能是分数、结论或建议。**

## 五、总体架构

```text
前端对话
  → POST /api/v1/chat（或 SSE /chat/stream）
  → 站点统一模型（服务端环境变量，无 BYOK）
  → LangGraph 小图（无 checkpointer，状态每次显式传入）
       classify
         ├─ crisis / boundary / high_domain / blocked / off_task / support / self_blame / greeting → fixed
         └─ explain / trend / summary / clarify
               → retrieve（知识库 top3，BM25 + 可选向量）
               → generate（场景 prompt + 场景策略）
               → validate（禁词 / 数字白名单 / 引用 / 边界声明 / 长度 / PII）
                    ├─ pass → 返回
                    └─ fail → 场景模板兜底
  → 回答 + citations + intent + risk → 写 chat_messages 与 ai_runs
```

## 六、LangGraph 设计

### 6.1 State（主要字段）

```python
class AgentState(TypedDict):
    question: str
    facts: dict          # 本次测评指标 + 可选 trend 子块
    history: list        # 最近若干条对话
    memory: dict         # 画像 / 摘要 / 建议记录
    scene: str           # chat_explain | trend | report
    intent: str
    chunks: list
    citations: list
    text: str
    source: str          # llm | template
    code: str
    validation: list
```

### 6.2 节点

| 节点 | 职责 | 失败处理 |
| --- | --- | --- |
| `classify` | 意图识别：规则优先；模糊时调一次 LLM 兜底分类（闭集、只判不写） | 失败即沿用规则结果 |
| `retrieve` | 知识库检索 top3（BM25 + 可选向量） | 空结果 → 无引用回答或“不猜” |
| `generate` | 场景 prompt + 站点模型 | 未配置/超时/限流 → 场景模板 |
| `validate` | 硬校验（禁词/数字/长度）与软校验（引用/边界声明） | 硬失败 → 场景模板；软失败只记录 |
| `fixed` | 危机/越界/高风险/拦截/支持/自责/问候等固定话术 | 不调模型 |
| `no_trend` | 不足两次测评时的固定话术 | 不调模型 |

### 6.3 意图与优先级

规则命中顺序：**crisis → boundary → blocked → high_domain → self_blame → support → off_task → unrelated → trend → clarify/explain**（安全类恒优先）。

- `crisis`：危机词命中，固定话术含 12356 与 120；
- `boundary`：疾病/用药/诊断类问题，拒答并给替代路径；
- `blocked` / `off_task`：内容红线与“跑代码/改文件”类请求，直接拒绝；
- `trend`：有趋势词且已有两次以上测评；否则 `trend_no_data`；
- 模糊问题（如“那个呢”）才允许 LLM 兜底分类，且有四条不变式：安全红线不可降级、只在模糊时调用、闭集失败即回退、改判必须与可支撑的数据相容。

### 6.4 场景策略

| 场景 | 长度上限 | 引用 | 边界声明 | 附加禁词 |
| --- | --- | --- | --- | --- |
| 对话解释 | 200 字 | 软 | 软 | — |
| 趋势解释 | 300 字 | 软 | 软 | 进步 / 退步 |
| 报告解读 | 150 字 | 关 | 关 | — |

策略表集中在 `agent/policies.py`，报告解读与对话共用同一张图与同一套校验。

### 6.5 模型与 Key

- 站点统一模型：`MM_LLM_BASE_URL` / `MM_LLM_MODEL` / `MM_LLM_API_KEY` 只在服务端环境变量；
- 不使用 BYOK、不把 Key 存库或下发浏览器；OpenAI 兼容接口，超时 45s；
- 支持非流式与 SSE 流式（`/chat/stream`）；
- 不调用外部工具/网页；只读 facts、记忆与知识块。

## 七、记忆系统

| 类型 | 内容 | 表 | 使用 |
| --- | --- | --- | --- |
| 短期 | 最近 20 条消息 | `chat_messages` | 当前对话 |
| 画像 | 目标 / 偏好 / 约束 | `memory_profile` | 情境化建议（需用户确认） |
| 摘要 | 每次测评的维度 / 最低项 / 建议 / 变化 | `memory_summaries` | 长期跟踪 |
| 建议 | 展示 / 完成 | `memory_advice` | 避重 |
| 心智画像 | 代码按规则生成的“本次表现描述” | 运行时计算（`GET /memory/mind-profile`） | 记忆页展示，不调模型 |

规则：画像确认后写入；摘要由模板生成并引用 facts；不存原始音频/转写全文；用户删除后不再引用；记忆检索带最近摘要 + 画像 + 当前 facts，控制 token。

## 八、RAG 知识库

- 语料：8 项维度、任务说明、计分边界、影响因素、局限与安全、练习建议，共 42 块；
- 元数据：`id / category / dims / title / text / source / version / risk / review_status / tags`；
- 门禁：只有 `review_status = reviewed` 的块进入检索；
- 检索：BM25（默认）+ pgvector 可选，RRF 融合，top3；命中不足时明确说“不知道”；
- 引用：回答带来源；用户可见文本不显示 `kb-` 编号，改显示标题。

## 九、校验与降级

### 9.1 硬校验（失败即模板）

1. 禁用词：诊断/治疗/康复/正常/异常/抑郁/焦虑症/智商/脑龄等临床与能力定级词；
2. 数字：只允许 facts 里的数字及其确定性派生（同维度加差、整数百分比、毫秒→秒）；
3. 长度：按场景（200 / 300 / 150 字）；
4. PII：手机号、身份证号等敏感信息不进入模型；
5. 内容红线：色情 / 暴力 / 政治类请求直接拒绝（`blocked`）。

### 9.2 软校验（记录不判死）

- 缺少知识库引用（有知识块时）；
- 缺少“这些数字不能说明什么”的边界声明。

软校验结果写入 `ai_runs.validation`，用于评测与改进，不阻断回答。

### 9.3 降级表

| 情况 | 处理 |
| --- | --- |
| 模型未配置 / 超时 / 限流 / 空返回 | 场景模板 |
| 硬校验失败 | 场景模板 |
| 检索无结果但 facts 可答 | 无引用回答 |
| 检索无结果且 facts 不足 | “我不猜” |
| 不足两次测评却问趋势 | 固定话术（trend_no_data） |
| 断网 | 前端提示 + 模板 |

## 十、隐私与安全

| 项 | 要求 |
| --- | --- |
| 数据出设备 | 只发 facts、记忆摘要、知识块；不发身份信息/原始音频/完整对话 |
| 模型 Key | 只在服务端环境变量；不写日志、不入库、不下发浏览器 |
| 对话 | 最近 20 条；用户可清空 |
| 删除 | 删除账号即清理；删除后不再引用 |
| 越界 | 医疗/用药/诊断拒答；危机固定资源 |
| 日志 | 不记录 Key、密码、完整对话；`MM_EXPOSE_LOGS=false` |

## 十二、评测

- 单元/集成：Python pytest 覆盖分类、校验、数字派生、趋势组装、统一出口；
- 前端：12 套纯逻辑测试 + Playwright E2E（注册 → 测评 → 报告 → 对话 → 记忆 → 复测）；
- 评测用例：意图分类、越界/危机、换算拒绝、自责重导向、趋势解释；
- 口径：禁用词 0、幻觉数字 0、引用可追溯；模板兜底率进入 `ai_runs` 统计。
