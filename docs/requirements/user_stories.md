## 一、写法与用法

- 每条故事只描述**一个用户在**一次使用中能感知到的**一个完整价值**，规模控制在 3 人日以内（INVEST 的 Small）。
- 故事正文用「角色 / 功能 / 价值」三段式；验收条件用 Gherkin（Given–When–Then）写，条件是**可判定**的：测试的人不需要问"这算不算通过"。
- 数字都有出处：性能指标来自 NFR-01～NFR-06，试次来自功能需求规范第六节，措辞要求来自 BR-01～BR-05。
- 一条故事只有在全部验收条件通过时才算完成；没通过的写回待办，不算"基本完成"。

## 四、故事详情

### US-01 首页看清产品是什么（P0 · 0.5 人日）

**角色**：作为一名第一次听说 MindMeter 的大学生
**功能**：我想在打开页面后一眼看清它测哪四个维度、要花多久、是不是医疗诊断
**价值**：从而判断值不值得投入 15 分钟

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 首次打开首页
  Given 用户第一次打开 MindMeter，且本地没有任何测评记录
  When 页面在 4G 网络下加载完成
  Then 应在 3 秒内显示四个维度名称（工作记忆、抑制控制、加工速度、情景记忆）与“约 15 分钟”的时长说明
  And 应显示“本产品不是医疗器械，不提供临床诊断”的声明
  And 在 360px 宽的屏幕上不应出现横向滚动，“开始测评”无需滚动即可见
  And 文案中不出现“智商”“诊断”“异常”等词

场景: 点击开始
  Given 用户停留在首页
  When 用户点击“开始测评”
  Then 应进入知情同意页，而不是直接进入第一个游戏
```

### US-02 两项确认后才开始（P0 · 0.5 人日）

**角色**：作为一名不想注册账号、在意隐私的用户
**功能**：我想在开始前确认数据只存在本机、并且随时可以删除
**价值**：从而放心把自己的认知表现交给这个页面

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 两项确认缺一不可
  Given 用户已进入知情同意页，两项勾选均未选中
  When 用户只勾选“我已满 18 岁”
  Then “开始测评”按钮应保持不可用
  And 页面应写明“数据仅保存在本机浏览器，可随时清除，清除后不可恢复”
  When 用户再勾选“我理解本产品非诊断用途”
  Then 按钮应变为可用

场景: 未满 18 岁
  Given 用户取消了“我已满 18 岁”的勾选
  When 用户尝试继续
  Then 页面应提示“本产品仅面向 18 岁及以上用户”并停留在同意页

场景: 刷新后需重新确认
  Given 用户此前已勾选过两项
  When 用户刷新同意页
  Then 两项勾选应恢复为未选中，用户必须重新确认
```

### US-03 正式计时前先练一遍（P0 · 1 人日）

**角色**：作为一名第一次做这类反应时游戏的用户
**功能**：我想在正式计时前先练两次
**价值**：从而不会因为不熟悉操作而拿到失真的低分

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 开始正式试次前先做练习
  Given 用户已通过知情同意，停留在工作记忆游戏的说明页
  When 用户点击“开始练习”
  Then 系统应执行 2 次练习试次，且练习结果不计入最终分数
  And 顶部进度应显示“第 1 / 4 个 · 工作记忆”
  And 练习结束后应提示“练习结束，正式测评开始”，再进入 8 次正式试次

场景: 点击到反馈的延迟
  Given 用户处在任意一个游戏的正式试次中
  When 用户点击屏幕
  Then 从点击到界面变化的间隔应不超过 100 毫秒
  And 该间隔以 pointerdown 记录 performance.now()、下一次 requestAnimationFrame 内再取一次的方式测量
```

### US-04 看到四维分数和雷达图（P0 · 2 人日）

**角色**：作为一名刚做完四个游戏的用户
**功能**：我想看到四维分数和一张雷达图
**价值**：从而知道自己在哪一项上偏弱，而不是只拿到一个笼统的总分

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 四维数据齐全时生成报告
  Given 用户已完成 4 个游戏，且每个游戏的有效试次占比不低于 80%
  When 第 4 个游戏结束
  Then 系统应在 2 秒内展示报告页
  And 报告应包含四维雷达图和 4 个 0–100 的整数分数
  And 每个维度应有一句中性解释，不出现“很差”“很聪明”等评价
  And 页面应显式标注“课程演示参考分，非常模、非临床”

场景: 出现数据不足
  Given 某个游戏因异常中断，未完成试次超过 20%
  When 报告生成
  Then 该维度应显示“数据不足”，而不是 0 分
  And 综合分应显示为“—”，并说明“数据不完整时不计算综合分”
```

### US-05 拿到针对弱项的建议（P0 · 1 人日）

**角色**：作为一名测完发现某项偏弱、想改善的用户
**功能**：我想拿到 2–3 条针对最弱维度的具体动作
**价值**：从而知道下一步练什么，而不是看完分数就结束

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 按最低维度给建议
  Given 用户完成了四个游戏
  When 报告生成
  Then 建议区应给出 2–3 条建议，且全部取自四维中分数最低的 1–2 个维度
  And 每条建议应为可执行动作，例如“每天 10 分钟双 n-back 练习”
  And 文案不得出现“治疗”“提升智商”“改善注意力缺陷”等表述

场景: 文案集中维护
  Given 产品负责人修改了建议文案配置
  When 刷新报告页
  Then 新文案应生效，且不需要改动计分逻辑或页面结构代码
```

### US-06 一键清除全部数据（P0 · 0.5 人日）

**角色**：作为一名把设备借给别人的用户
**功能**：我想一次性删掉本机保存的全部测评记录
**价值**：从而在分享设备前不留下自己的认知数据

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 清除本地记录
  Given 用户本地存有 3 条测评记录
  When 用户在设置页点击“清除全部数据”
  Then 系统应弹出二次确认，说明“清除后不可恢复”
  When 用户确认
  Then 本地全部记录应被删除，历史页显示“暂无记录”
  And 再次打开页面时不应出现已删除的记录

场景: 存储写入失败
  Given 浏览器处于隐私模式或存储空间已满
  When 测评结束尝试写入记录
  Then 系统应提示“保存失败，本次结果不会被保留”
  And 不得显示“已保存”或假装写入成功
```

### US-07 对比两次测评的变化（P1 · 1.5 人日）

**角色**：作为一名隔了一周回来复测的用户
**功能**：我想看到这次和上次的分数变化
**价值**：从而判断自己的状态有没有变化，而不是只记住上次一个模糊的数

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 第二次测评后的对比
  Given 用户本地已有一条完成于 7 天前的测评记录
  When 用户完成第 2 次测评
  Then 报告页应显示每个维度的变化值（本次分数 − 上次分数）
  And 应提示“复测间隔建议 7 天以上，变化不等于训练效果”

场景: 只有一次记录时
  Given 用户本地只有 1 条测评记录
  When 用户打开历史页
  Then 页面应提示“再测一次才能对比变化”，而不是显示空白或 0 值

场景: 立即复测
  Given 用户刚刚完成一次测评
  When 用户在 7 天内再次开始测评
  Then 系统应允许开始，但提示练习效应可能影响结果
  And 不得阻止用户继续
```

### US-08 刷新后从当前游戏继续（P1 · 1.5 人日）

**角色**：作为一名中途被叫走、误关页面的用户
**功能**：我想刷新后从当前游戏继续
**价值**：从而不用把已经做完的两个游戏重做一遍

**验收标准 (Acceptance Criteria - Gherkin 语法)**

```gherkin
场景: 刷新后恢复进度
  Given 用户已完成工作记忆与抑制控制两个游戏，正处在加工速度游戏内
  When 用户刷新页面
  Then 前两个游戏的结果应被保留
  And 应从加工速度游戏的说明页重新开始，而不是回到首页重测
  And 已完成的游戏不应被要求重新作答

场景: 中途退出
  Given 用户处在任意一个游戏进行中
  When 用户点击“退出”
  Then 系统应弹出二次确认
  And 用户确认后回到首页，已完成游戏的结果仍保留在本地
```

## 五、INVEST 自检

| 故事 | I 独立 | N 可协商 | V 有价值 | E 可估算 | S 小 | T 可测 |
| --- | --- | --- | --- | --- | --- | --- |
| US-01 | ✓ 不依赖其他故事 | ✓ 文案与版式可调 | ✓ 决定用户是否开始 | ✓ 0.5 人日 | ✓ 单页 | ✓ 3 秒、360px 可量 |
| US-02 | ✓ 独立于游戏 | ✓ 措辞可改 | ✓ 隐私顾虑直接影响开始率 | ✓ 0.5 人日 | ✓ 单页 | ✓ 按钮状态可判定 |

| US-04 | ✓ 依赖四个游戏能跑 | ✓ 图表形式可换 | ✓ 产品核心价值 | ✓ 2 人日 | ✓ 单页 | ✓ 2 秒可计时 |
| US-05 | ✓ 依赖 US-04 | ✓ 文案可改 | ✓ 从"看到"到"知道做什么" | ✓ 1 人日 | ✓ 单模块 | ✓ 取最低维度可验 |
| US-06 | ✓ 完全独立 | ✓ 入口位置可调 | ✓ 借设备前能删干净 | ✓ 0.5 人日 | ✓ 一个动作 | ✓ 删除后可检查 |
| US-07 | ✓ 依赖 US-06 的数据结构 | ✓ 呈现方式可换 | ✓ 复测闭环 | ✓ 1.5 人日 | ✓ 单页 | ✓ 差值可核对 |
| US-08 | ✓ 依赖 US-03 | ✓ 恢复粒度可调 | ✓ 避免重做，降低放弃率 | ✓ 1.5 人日 | ✓ 一个机制 | ✓ 刷新即可验 |
