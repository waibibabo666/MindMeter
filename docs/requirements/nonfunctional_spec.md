> L2 引入账号、后端、数据库、Agent 与 RAG，NFR 从“静态站点底线”升级为“小型产品底线”。仍然不追求企业级多区域/等保/K8s。

## 二、目的与范围

本文定义 MindMeter L2 的质量门槛：性能、可靠性、安全、隐私、可用性、兼容性、可维护性、可观测性、AI 质量与成本。

不覆盖：

- 多区域容灾、K8s、服务网格、Vault、Prometheus 全家桶；
- 等保、ISO 27001、SOC 2、付费渗透测试；
- 全站 WCAG 2.1 AA 认证；
- 7×24 值班；
- 临床常模/信效度验证。

## 四、详细非功能需求

### 4.1 性能（NFR-PERF）

| ID | 指标 | 目标 | 条件 |
| --- | --- | --- | --- |
| NFR-PERF-01 | 首屏 LCP | p75 ≤2.5s | 4G、中端安卓、冷启动 |
| NFR-PERF-02 | 首包体积 | ≤500KB（gzip，不含题库图片） | 首页 |
| NFR-PERF-03 | 非 AI API | p95 ≤500ms，p99 ≤1s | 服务端处理，不含网络 |
| NFR-PERF-04 | 任务输入反馈 | p95 ≤100ms | 点击/键盘到视觉反馈 |
| NFR-PERF-05 | 服务端计分 | p95 ≤200ms | 单次提交 |
| NFR-PERF-06 | RAG 检索 | p95 ≤200ms | pgvector top 3 |
| NFR-PERF-07 | AI 完整响应 | p95 ≤30s，超时 45s | M1 非流式 |
| NFR-PERF-08 | AI 首字 | ≤3s（M2 流式） | SSE |
| NFR-PERF-09 | 并发 | 50 并发作答；500 DAU | 演示容量 |
| NFR-PERF-10 | 数据库查询 | p95 ≤100ms | 常用索引 |

### 4.2 可靠性（NFR-REL）

| ID | 要求 | 目标 |
| --- | --- | --- |
| NFR-REL-01 | 可用性 | 月度 ≥99.0%（M3 目标） |
| NFR-REL-02 | 提交幂等 | 同一 assessment 重复提交返回同一结果 |
| NFR-REL-03 | 数据不丢 | 已确认提交的测评/分数不丢 |
| NFR-REL-04 | 断点 | 每任务写服务端 draft；刷新恢复 |
| NFR-REL-05 | 备份 | 托管 Postgres 每日备份，保留 7 天 |
| NFR-REL-06 | RTO/RPO | RTO ≤4h；RPO ≤24h |
| NFR-REL-07 | 迁移 | Alembic 迁移可回退 |
| NFR-REL-08 | AI 降级 | 模型失败/超时回退模板，不阻塞报告/趋势 |
| NFR-REL-09 | 单会话 | 同一用户同一时间一个活跃作答会话；多标签提示接管 |

### 4.3 安全（NFR-SEC）

| ID | 要求 | 目标 |
| --- | --- | --- |
| NFR-SEC-01 | 传输 | HTTPS/HSTS；TLS 1.2+ |
| NFR-SEC-02 | 密码 | argon2id（或 bcrypt cost≥12）；禁止明文/弱密码 |
| NFR-SEC-03 | 认证 | 短期 access + 可轮换 refresh；登出撤销；失败限流 |
| NFR-SEC-04 | 授权 | 所有测评/报告/记忆按 user_id 校验；越权返回 404 |
| NFR-SEC-05 | BYOK Key | AES-GCM/Fernet 加密存库；主密钥只放环境变量；不写日志/导出 |
| NFR-SEC-06 | 输入 | 所有输入/模型输出转义；禁止 `eval`；SQL 参数化 |
| NFR-SEC-07 | 限流 | 登录、注册、AI 调用、导出分级限流 |
| NFR-SEC-08 | 依赖 | 锁定版本；CI 扫描高危漏洞；7 天内修复高危 |
| NFR-SEC-09 | 密钥 | 仓库零密钥；`.env` 不入库；CI secret 扫描 |
| NFR-SEC-10 | 审计 | 删除/导出/管理操作留痕；保留 ≥180 天 |
| NFR-SEC-11 | CORS/CSRF | 只允许前端域名；Cookie 模式加 CSRF；JWT 不放 URL |
| NFR-SEC-12 | 漏洞 | 无高危/严重漏洞；上线前 ZAP/依赖扫描 |

### 4.4 隐私与数据（NFR-PRIV）

| ID | 要求 | 目标 |
| --- | --- | --- |
| NFR-PRIV-01 | 最小化 | 不收集姓名、手机号、学校、公司、年龄、学历 |
| NFR-PRIV-02 | 同意 | 注册/测评前说明存储、使用、AI、模型厂商；主动勾选 |
| NFR-PRIV-03 | 数据分类 | 账号/测评/记忆/对话为敏感；Key 为高敏感 |
| NFR-PRIV-04 | 保留 | 账号存续期；删除后 30 天清除；对话 20 条 + 摘要 |
| NFR-PRIV-05 | 删除 | 单条/全部/注销；二次确认；不可恢复 |
| NFR-PRIV-06 | 导出 | JSON；不含密码/Key；15 个工作日内（M1 即时） |
| NFR-PRIV-07 | 数据出境 | 模型由用户选择的厂商处理；页面披露；不上传原始音频 |
| NFR-PRIV-08 | 日志脱敏 | 不记录 Key、密码、完整对话、完整邮箱 |
| NFR-PRIV-09 | 无追踪 | 不接广告 SDK、第三方统计、社交登录 |
| NFR-PRIV-10 | 未成年人 | 18+；未满 18 阻止注册 |
| NFR-PRIV-11 | 审计 | 管理员不查看用户对话；如必须，审批+留痕 |

### 4.5 可用性与无障碍（NFR-USA）

| ID | 要求 | 目标 |
| --- | --- | --- |
| NFR-USA-01 | 移动 | 360px 起可用；按钮 ≥44×44px |
| NFR-USA-02 | 键盘 | 登录/测评/报告/对话关键路径可键盘完成 |
| NFR-USA-03 | 对比度 | 正文 ≥4.5:1，大字 ≥3:1 |
| NFR-USA-04 | 非颜色唯一 | 对错/状态同时用文字或形状 |
| NFR-USA-05 | 减少动效 | 尊重 `prefers-reduced-motion` |
| NFR-USA-06 | 文案 | 避免临床化措辞；关键结论可理解率 ≥80% |
| NFR-USA-07 | 错误 | 说明“发生了什么、下一步怎么办” |

### 4.8 可观测性（NFR-OBS）

| ID | 要求 | 目标 |
| --- | --- | --- |
| NFR-OBS-01 | 日志 | JSON；trace_id、user_pseudonym、path、status、latency；无 PII/Key |
| NFR-OBS-02 | AI 运行 | `ai_runs` 记录模型、耗时、降级、校验、token 估算 |
| NFR-OBS-03 | 指标 | 请求量、错误率、p95、AI 成功率、RAG 命中率 |
| NFR-OBS-04 | 告警 | 错误率/延迟/数据库/AI 失败；M3 接入免费告警 |
| NFR-OBS-05 | 保留 | 应用日志 30 天；审计 180 天 |
| NFR-OBS-06 | 评测 | 30 条 Agent 用例 + 20 条 RAG 检索用例 |

### 4.9 AI 质量（NFR-AI）

| ID | 要求 | 目标 |
| --- | --- | --- |
| NFR-AI-01 | 依据 | 回答只引用 facts/记忆/知识块；无依据说“不知道” |
| NFR-AI-02 | 数字 | 输出数字必须来自 facts；幻觉数字 0 |
| NFR-AI-03 | 建议 | 只改写固定建议库；新增建议 0 |
| NFR-AI-04 | 禁用词 | 诊断/治疗/疗效/正常/异常/提升智商/脑龄等 0 次 |
| NFR-AI-05 | 越界 | 医疗/用药/诊断拒答；危机固定资源，不调模型 |
| NFR-AI-06 | 引用 | 回答附 source；引用率 ≥90% |
| NFR-AI-07 | 降级 | 失败/超时/校验不过 → 模板；报告不空 |
| NFR-AI-08 | 评测 | 30 条：准确/有依据/有用/无越界各 ≥4/5 |

## 五、约束

| 类别 | 约束 | 影响 |

## 七、发布底线

- 注册→测评→报告→对话→记忆→复测→趋势全链路可走通；
- 服务端计分与金标准一致；重复提交幂等；
- 无总分/常模/百分位；未测显示“未测”；
- Key 加密存库，不出现在日志/导出/前端源码；
- 删除账号 30 天内清除；导出完整；
- Agent 30 条评测通过；禁用词 0；幻觉数字 0；
- AI 失败回退模板；报告/趋势不空；
- 备份/恢复演练至少 1 次；
- 无高危漏洞；移动端可用。

## 八、明确不做

- 多区域容灾、K8s、服务网格、Vault、Prometheus 全家桶；
- 等保、ISO 27001、SOC 2、付费渗透测试；
- 全站 WCAG 2.1 AA 认证；
- 7×24 值班；
- 临床常模/信效度验证；
- B 端/多语言/原生 App。
