## 二、目的与范围

本文只规定 6 周 MVP **必须达到**的质量底线，不写企业级运维和合规要求。判断标准是：4 个人能不能做完、课程演示能不能稳定跑、用户能不能顺利测完。

## 三、质量目标

| ID | 类别 | 要求 | 目标 | 怎么验证 |
| --- | --- | --- | --- | --- |
| NFR-01 | 性能 | 首屏加载 | 4G 下 ≤3 秒 | Lighthouse、真机 |

## 四、体验底线

- 每个游戏开始前必须有说明和练习，用户知道“要做什么、按什么、多久”；
- 页面必须显示当前进度（第几个游戏/共 4 个）和剩余大致时间；
- 任何错误提示都要说明“发生了什么、下一步怎么办”；
- 中途退出必须二次确认，不能一点就丢；
- 报告首屏先给结论和雷达图，不要求用户先读长文；
- 手机端单手可完成主要操作，按钮不小于 44×44px。

## 五、隐私与伦理底线

- 不收集真实姓名、手机号、身份证号、学校、公司等可识别信息；
- 不要求注册，不接入广告 SDK、社交登录和第三方统计；
- 数据只保存在用户浏览器，用户可随时清除；
- 开始前必须让用户主动勾选“已阅读说明并同意”；
- 不提供诊断、治疗、药物或危机干预建议；
- 不宣称“提升智商”“治疗注意力缺陷”等效果；
- 报告必须写明样本少、无临床常模、结果受当天状态影响。

## 六、本期明确不做

以下要求对一个 4 人/6 周的课程项目没有必要，本期不纳入验收：

- 99.9% 可用性、RTO/RPO、异地容灾、每日备份；
- 等保备案、DPIA、ISO 27001、渗透测试；
- 多语言、多时区、多币种；
- 全站 WCAG 2.1 AA 认证；
- 全链路监控、告警值班、日志平台；
- 压力测试、千人并发、自动扩缩容；
- 应用商店上架、原生 App 适配；
- 7×24 客服和工单系统。

## 七、验收方式

| 项目 | 方法 | 通过标准 |
| --- | --- | --- |
| 性能 | Lighthouse + 手动计时 | NFR-01～04 达标 |
| 兼容 | Chrome/Edge/Safari + 一台 iPhone/Android | 核心流程无阻断 |
| 可靠 | 刷新、断网、关标签页 | 已完成游戏不丢，当前游戏可恢复 |
| 易用 | 10–15 人用户测试 | 完成率 ≥80%，理解率 ≥4/5 |
| 隐私 | 代码检查 + 演示 | 无身份字段、无第三方追踪、可清除 |
| 科学 | 单元测试 + 文案评审 | 同输入同输出，标注非临床 |
| 部署 | 线上访问 + 手机热点 | 可公开访问，演示稳定 |

## 八、约束

| 约束 | 说明 |
| --- | --- |
| 时间 | 6 周，W1–W6，每周一个可演示增量 |
| 人力 | 4 人，均为课程项目兼职投入 |
| 预算 | 尽量零成本，静态托管免费额度优先 |
| 技术 | Web 前端为主，不引入重型后端和数据库 |
| 合规 | 非临床、非诊断；不收集敏感身份信息 |
| 数据 | 本地存储，样本量小，不宣称常模 |

## 九、发布底线

满足以下条件才能在第 6 周演示：

- 4 个游戏都能完整跑通，总时长不超过 15 分钟；
- 报告能生成，分数和文案没有明显错误；
- 手机端可操作，刷新不丢已完成结果；
- 隐私提示、数据清除、非诊断声明都在；
- 线上链接可访问，另备一份本地版本和演示视频；
- 没有阻塞演示的控制台报错。
