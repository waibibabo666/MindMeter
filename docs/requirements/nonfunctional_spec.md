## 1. 引言

### 1.1 目的

本文定义 MindMeter 的可度量质量门槛，回答「做到什么程度才算合格」，并规定验证方法与发布门禁。功能需求回答「做什么」，本文回答「做得多好、如何证明」。

### 1.2 范围

覆盖性能与容量、可靠性、安全、隐私合规、可用性与无障碍、兼容性、可维护性、可观测性、数据与科学质量、本地化、法律伦理与成本。

不覆盖具体技术选型与实现方案（见[软件设计](../software.md)）。

### 1.3 目标值与确认状态

- 文中数值为 **v0.1 建议目标**，用于架构与测试设计；带「【待定】」的需在 M1 评审确认。
- 任何目标下调必须记录理由、影响与补偿措施，并经技术负责人与产品负责人批准。
- 指标必须在预发布环境或生产灰度中验证，不能只凭设计声明。

### 1.4 质量模型

参考 ISO/IEC 25010 质量模型，结合心理测评产品的特殊性（科学性、隐私、伦理）扩展「数据与科学质量」「法律与伦理」两类。

| NFR-PERF-013 | 慢查询占比 | ≤ 1% | 生产数据库，日统计 | P1 |
| NFR-PERF-014 | CDN 命中率 | ≥ 95% | 静态资源 | P2 |

**容量假设**：

- 单次测评约【待定：60–120】次写请求；
- 峰值集中在晚间 20:00–23:00 与内容投放后 2 小时；
- 自动扩缩容需在 5 分钟内完成，扩容期间不得丢失会话。

**降级策略**：

- 报告生成排队时，先返回「生成中」并通知，不阻塞提交；
- 非核心（推荐内容、趋势图）失败不影响报告核心内容；
- 第三方分析/监控不可用时，核心流程继续。

| NFR-REL-007 | 备份 | 每日全量 + 增量；保留 30 天 | 加密存储，异地/跨可用区 |
| NFR-REL-008 | 恢复演练 | 每季度 1 次 | 记录实际 RTO/RPO |
| NFR-REL-009 | 幂等性 | 提交/支付/删除 100% 幂等 | 重复请求不产生副作用 |
| NFR-REL-010 | 故障隔离 | 单模块故障不影响登录与作答 | 超时、熔断、降级 |
| NFR-REL-011 | 数据一致性 | 报告与作答、计分版本一致 | 对账任务每日校验 |

**关键故障场景**：

| 场景 | 期望行为 |
| --- | --- |
| 计分服务不可用 | 作答落库，任务排队；恢复后自动重算；用户可查状态 |
| 数据库主库故障 | 自动切换；未提交会话可恢复；已提交数据不丢 |
| 支付回调丢失 | 主动对账；权益延迟但可补发；不重复扣款 |
| 短信服务故障 | 备用通道/邮件；提示稍后重试；不阻断已登录用户 |
| CDN 故障 | 回源；静态资源可降级；监控告警 |

| NFR-SEC-006 | 应用安全 | OWASP ASVS L2；无高危/严重漏洞 | SAST/DAST/渗透 |
| NFR-SEC-007 | 依赖安全 | 每次构建扫描；高危 7 天内修复 | CI 报告 |
| NFR-SEC-008 | 速率限制 | 登录、验证码、提交、导出分级限流 | 压测/滥用测试 |

| NFR-SEC-010 | 审计日志 | 敏感操作全量；保留 ≥180 天；防篡改 | 抽查 |
| NFR-SEC-011 | 渗透测试 | 上线前 1 次，之后每年 1 次 | 报告与修复记录 |
| NFR-SEC-012 | 安全开发 | 威胁建模、代码评审、依赖锁定 | 流程审计 |
| NFR-SEC-013 | 后台防护 | 独立域名/访问控制、禁止索引、IP/设备策略【待定】 | 配置检查 |
| NFR-SEC-014 | 事件响应 | 预案、联系人、演练；P0 15 分钟内响应 | 演练记录 |

**安全原则**：

- 默认拒绝、最小权限、纵深防御；
- 不信任客户端输入，所有计分相关数据以服务端为准；
- 日志中禁止出现验证码、密码、完整作答、完整手机号；
- 第三方脚本（统计、客服）需经安全评审，禁止读取测评 DOM 中的敏感内容。
