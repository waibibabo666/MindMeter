## 二、目的与范围

本文定义 MindMeter 六周 MVP 的功能边界和验收标准。首版只做一件事：让用户在 15 分钟内完成 4 个认知小游戏，看到自己的四维画像和建议。

**本期做**：4 个游戏、计分、报告、建议、本地历史、复测对比、数据清除。

**本期不做**：账号登录、支付、运营后台、AI 解读、自适应测评、临床常模、社区、原生 App。6 周时间只够把核心体验做扎实。

## 三、用户与前提

| 角色 | 说明 |
| --- | --- |
| 体验者 | 18–30 岁大学生/职场新人，无需注册，打开网页即可测评 |
| 项目组 | 维护游戏配置、计分规则和文案，不面向用户提供后台 |

前提：

- 用户使用 Chrome、Edge、Safari 等现代浏览器；
- 测评数据保存在用户本地浏览器，不收集姓名、手机号等身份信息；
- 用户需确认已满 18 岁并理解“本产品不是临床诊断”；
- 首版仅简体中文。

## 四、核心流程

1. 打开首页，了解产品是什么、需要多久、能测什么；
2. 阅读并勾选知情同意与隐私提示；
3. 查看测评说明，完成每个游戏的练习；
4. 依次完成 4 个游戏：工作记忆 → 抑制控制 → 加工速度 → 情景记忆；
5. 前端计分，生成四维画像；
6. 查看报告：分数、雷达图、解释、建议、局限；
7. 结果保存在本地，可复测、查看历史或清除数据。

## 六、四个游戏的规则

| 游戏 | 玩法 | 试次 | 主要指标 | 目标时长 |
| --- | --- | --- | --- | --- |
| 工作记忆 | 屏幕依次闪现方块/数字序列，用户按顺序复现；长度从 3 逐步增加到 7 | 2 次练习 + 8 次正式 | 最长正确长度、正确率 | 3 分钟 |
| 抑制控制 | 看到绿色圆点尽快点击，看到红色圆点不点（Go/No-Go） | 2 次练习 + 40 次正式（约 25% No-Go） | 正确率、误报次数、平均反应时 | 3 分钟 |
| 加工速度 | 屏幕出现目标后尽快点击；目标出现前有 1–3 秒随机等待 | 2 次练习 + 20 次正式 | 中位反应时、漏答次数 | 2 分钟 |
| 情景记忆 | 先看 12 个词语/图片 20 秒，再从 24 项中判断“见过/没见过” | 1 次练习 + 24 次正式 | 再认正确率、误报率 | 4 分钟 |

规则细节：

- 所有游戏开始前必须有练习，练习结果不计入分数；
- 反应时类游戏允许鼠标、触屏和键盘操作；
- 每个游戏结束后展示一句中性反馈，不显示“你很差/你很聪明”等评价；
- 游戏参数（试次、时长、阈值）集中放在配置文件中，便于调整。

## 七、计分与报告

### 7.1 计分

1. 每个游戏输出 1–2 个原始指标（如最长长度、正确率、中位反应时）。
2. 将原始指标按团队设定的最小/最大值线性映射到 0–100 的**参考分**；超出范围截断到 0 或 100。
3. 四个参考分组成四维画像；不计算“总智商”或“脑力排名”。
4. 映射阈值写在 `scoring-config` 中并标注版本；报告页明确写“课程演示参考分，非常模、非临床”。

### 7.2 报告结构

1. 一句话摘要：本次测评的整体状态；
2. 四维雷达图；
3. 四个维度卡片：分数、原始指标、一句话解释；
4. 2–3 条行动建议（对应最低维度）；
5. 局限说明：样本少、无临床常模、受状态影响；
6. 复测入口与历史记录；
7. 免责声明与数据清除入口。

### 7.3 建议规则

- 取分数最低的 1–2 个维度，各给 1–2 条建议；
- 建议必须是具体动作，例如“每天 10 分钟双 n-back 练习”“减少多任务切换”；
- 不使用“治疗”“改善注意力缺陷”“提升智商”等表述；
- 建议文案集中配置，便于产品负责人统一修改。

## 八、数据与存储

首版不建账号、不接数据库，使用浏览器 `localStorage` 保存测评记录。

```json
{
  "version": 1,
  "sessions": [
    {
      "id": "uuid",
      "startedAt": "2026-10-19T20:00:00+08:00",
      "finishedAt": "2026-10-19T20:14:30+08:00",
      "results": {
        "workingMemory": { "maxSpan": 5, "accuracy": 0.75 },
        "inhibition": { "accuracy": 0.88, "commissionErrors": 3, "meanRt": 420 },
        "speed": { "medianRt": 310, "omissions": 1 },
        "memory": { "accuracy": 0.79, "falseAlarmRate": 0.12 }
      },
      "scores": {
        "workingMemory": 62,
        "inhibition": 78,
        "speed": 71,
        "memory": 66
      },
      "reportVersion": "1.0"
    }
  ]
}
```

要求：

- 不存储姓名、手机号、身份证号、精确地址等身份信息；
- 只存测评所需的数据和本地生成的时间戳；
- 存储写入失败（如隐私模式、空间不足）时提示用户，不假装保存成功；
- 用户可一键清除全部数据；
- 如后续增加导出，导出文件同样不含身份信息。

### 5.3 计分与报告（FR-300）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-301 | 自动计分 | P0 | 提交后自动触发；结果 ≤10 秒返回；同输入同版本结果一致；计分版本随会话固定，不受后续配置变更影响 |
| FR-302 | 效度校验 | P0 | 至少覆盖作答一致性、反应时异常、缺失/随机作答；输出可信等级与原因；低可信时不展示确定性结论 |
| FR-303 | 常模与百分位 | P0 | 按适用分层计算百分位与置信区间；无可用常模时展示原始分并明确说明；常模版本可追溯 |
| FR-304 | 多维画像 | P0 | 每个维度展示分数/百分位、描述性区间与一句话解释；不使用「好/坏/正常/异常」等诊断化标签；移动端可读 |
| FR-305 | 报告生成 | P0 | 报告包含：摘要、维度、可信度、解释、建议、局限、免责声明、求助资源；5 名目标用户测试中至少 4 人可在 10 秒内说出核心结论；支持同版本重新生成 |
| FR-306 | 解释与行动建议 | P0 | 建议 3–5 条，具体、可执行、可验证；与维度结果对应；不提供药物、治疗或诊断建议；标注不确定性 |
| FR-307 | 安全提示与危机资源 | P0 | 涉及自伤/自杀相关题目或关键词时，展示求助热线与紧急资源；说明产品不能提供危机干预；不因此自动标记用户为高风险或对外共享 |
| FR-308 | 报告版本与重算 | P1 | 旧报告不可原地篡改；重算生成新版本并标注差异；用户可查看历史版本 |
| FR-309 | 报告导出 | P1 | 支持通过浏览器打印生成 PDF；导出需登录与二次确认；文件包含报告编号与生成时间 |
| FR-310 | AI 辅助解读 | P2 | 本期不实现；如启用须明确标注 AI 生成、可关闭、不替代专业意见，输入脱敏并经安全过滤 |
| FR-311 | 自动化决策告知 | P0 | 报告结论与建议由规则/模型自动生成，须在报告页说明生成方式、依据维度与局限；用户可申请人工复核，5 个工作日内答复 |

**FR-302 低可信展示规则**：

- 低可信时只展示原始分、作答完整度与提示语，不展示百分位、等级标签与确定性建议；
- 提示用户谨慎参考，并给出重测建议；
- 该规则同样适用于分享卡片与导出文件。

**FR-305 报告结构（建议顺序）**：

1. 一句话结论 + 可信度徽标；
2. 多维画像图与维度卡片；
3. 结果解释（含「这意味着什么/不意味着什么」）；
4. 3–5 条行动建议；
5. 局限与下次复测建议；
6. 免责声明、生成方式说明与求助资源；
7. 分享/导出/删除入口。

**FR-307 安全规则**：

- 危机资源文案需经项目组与指导老师审核；
- 热线号码与地区必须可配置、可更新；
- 不做风险分级推送，不将危机信号用于营销；
- 相关事件单独记录，限制访问。

### 5.4 追踪与成长（FR-400）

| ID | 需求 | 优先级 | 验收标准 |

## 8. 接口需求

### 8.1 通用约定

- 风格：REST + JSON，路径版本 `/api/v1`；
- 认证：Bearer JWT（短期 access + 可轮换 refresh）；匿名会话使用受限 token；
- 时间：ISO 8601 UTC；数据库存 UTC，展示按 Asia/Shanghai；
- 幂等：提交、导出、删除等使用 `Idempotency-Key`；
- 错误：统一 `code/message/trace_id`，不泄露内部堆栈；
- 分页：cursor 优先；默认 20，最大 100；
- 限流：按用户/IP/接口分级，返回 `429` 与重试提示；
- 审计：敏感接口记录 actor、对象、结果与理由。

## 10. 测评会话状态机

| 状态 | 说明 | 允许的下一状态 |
| --- | --- | --- |
| `CREATED` | 已创建，未同意 | `CONSENTED`、`EXPIRED` |
| `CONSENTED` | 已同意，未开始 | `IN_PROGRESS`、`ABANDONED`、`EXPIRED` |
| `IN_PROGRESS` | 作答中 | `PAUSED`、`SUBMITTED`、`ABANDONED`、`EXPIRED` |
| `PAUSED` | 用户主动暂停（仅允许的题型） | `IN_PROGRESS`、`ABANDONED`、`EXPIRED` |
| `SUBMITTED` | 已提交，待计分 | `SCORING`、`FAILED` |
| `SCORING` | 计分中 | `SCORED`、`FAILED` |
| `SCORED` | 计分完成 | `REPORTED` |
| `REPORTED` | 报告可用 | 终态（可重算生成新版本） |
| `INVALID` | 效度过低/数据异常，由计分服务触发 | 终态；可引导重测 |
| `ABANDONED` | 用户放弃 | 终态 |
| `EXPIRED` | 超过 24 小时未完成 | 终态 |
| `FAILED` | 计分失败 | 重试回 `SCORING`（最多 3 次），超限转 `INVALID` 并保留作答 |

规则：

- 状态迁移必须原子化并记录时间、触发者与版本；
- 提交幂等：同一会话重复提交返回同一 `report_id`；
- 计分失败不得丢失作答；重试使用相同计分版本；
- 同一会话同一时间只允许一个活跃客户端，切换设备需显式接管；
- 任何终态都可被用户删除，但审计日志按规则保留。

## 12. 验收与发布标准

### 12.1 功能验收

### 12.2 发布门禁

| 门禁 | 标准 | 证据 |

| 安全 | 无高危漏洞，依赖扫描通过 | 安全报告 |

### 12.3 需求验收格式

每条需求至少有一个用例，采用 Given/When/Then 描述；示例（FR-205）：

```gherkin
Given 用户正在进行测评且已作答 10 题
When 用户刷新页面或断网后重新进入
Then 系统恢复到第 10 题并保留此前作答
And 恢复时间不超过 2 秒
And 若超过 24 小时，提示会话已过期并说明是否可重测
```
