## 1. 引言

### 1.1 目的

本文定义 MindMeter MVP 的功能边界、行为规则与验收标准，供产品、设计、开发、测试与合规共同使用。需求编号稳定，变更须走 §16 的流程。

### 1.2 范围

覆盖：账号与同意、测评执行、计分与报告、历史追踪、分享与隐私、运营后台、通知、数据权利。

不覆盖：临床诊断、治疗建议、心理咨询撮合、企业组织架构与席位计费、原生 App 专属能力（后续版本）。

### 1.3 读者

- 产品/项目：确认范围与优先级；
- 设计/前端：交互、状态与异常；
- 后端/算法：接口、数据与计分契约；
- QA：测试用例与验收；
- 法务/隐私：同意、数据权利与免责边界。

### 1.4 术语

| 术语 | 说明 |
| --- | --- |
| 测评（Assessment） | 一套固定版本的题目、计分规则与报告模板的集合 |
| 测评会话（Session） | 用户一次作答过程，含状态、作答、环境与时间信息 |
| 有效作答（Valid Response） | 通过完整性校验与效度规则、可用于计分的作答 |
| 常模（Norm） | 解释分数用的参照样本分布 |
| 低可信（Low Confidence） | 效度校验发现异常，结果仅作参考 |
| P0/P1/P2 | 必须/应该/可以；P0 未完成不得发布 |

## 2. 产品概述

### 2.1 产品目标

让普通用户在 20 分钟内完成一次可信、可理解的心智测评，并获得可执行的下一步建议；通过复测与趋势，把一次性测评转化为长期自我认知工具。

### 2.2 用户角色

| 角色 | 说明 | 关键权限 |
| --- | --- | --- |
| 游客 Visitor | 未登录用户 | 浏览公开内容、完成 1 次基础测评、查看临时报告 |
| 注册用户 User | 已注册并同意协议 | 保存报告、查看历史、管理隐私、申请导出/删除 |
| 付费用户 Subscriber | 已购买报告/订阅 | 注册用户权限 + 付费内容与增强报告 |
| 内容管理员 Editor | 运营/内容人员 | 题库草稿、内容发布、报告文案（受审批约束） |
| 系统管理员 Admin | 系统负责人 | 账号、权限、配置、审计；不默认查看作答明细 |
| 数据分析师 Analyst | 数据/增长 | 聚合看板与脱敏数据；禁止导出可识别个体 |
| 客服 Support | 用户支持 | 工单、同意记录、删除请求状态；不可见完整作答 |
| 心理测量顾问 Advisor | 外部/内部专家 | 量表与常模方案审批、效度报告只读 |

### 2.3 系统边界

| 内部 | 外部依赖 |
| --- | --- |
| Web 前端、Backend API、Core Engine、运营后台、数据库 | 短信/邮件服务、支付渠道、对象存储、CDN、错误监控、数据分析、第三方登录（如启用） |

外部服务必须签订数据处理协议（DPA），不得将作答原文或可识别信息传给广告类 SDK。

### 2.4 前提与约束

- 首版为响应式 Web，移动端优先；
- 首版仅简体中文；
- 首版限制 16 岁及以上（D-10 待确认）；
- 量表与常模必须获得授权/伦理许可后方可上线（D-01/D-02）；
- 所有面向用户的结论必须附免责声明与局限说明。

## 3. 核心用户旅程

```mermaid
flowchart LR
  A[内容/分享/搜索] --> B[测评详情]
  B --> C[知情同意]
  C --> D[环境检查]
  D --> E[测评作答]
  E --> F[完整性校验与提交]
  F --> G[计分与效度校验]
  G --> H[报告]
  H --> I{注册/登录?}
  I -->|是| J[保存并进入历史]
  I -->|否| K[临时报告]
  J --> L[趋势/复测/建议]
```

关键体验要求：

1. 从进入到开始测评不超过 3 次点击（不含同意勾选）；
2. 任一环节失败都可恢复，不丢失已作答内容；
3. 报告首屏必须让用户看懂「这是什么、有多可信、下一步做什么」；
4. 任何付费墙不得阻断用户查看自己的基础结果与隐私设置。

## 5. 详细功能需求

### 5.1 账号与身份（FR-100）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-101 | 游客测评 | P0 | 未登录用户可完成 1 次基础测评并查看报告；临时结果保留【待定：24 小时】；注册后可按提示合并到账号，合并前明确告知 |
| FR-102 | 注册与登录 | P0 | 支持手机号+验证码（首选）与邮箱+密码【待定】；验证码 5 分钟有效、错误次数受限；登录态默认 30 天；支持退出全部设备（P1） |
| FR-103 | 第三方登录 | P2 | 微信/Apple 登录【待定】；首次授权需绑定手机号；解绑与账号合并有明确路径 |
| FR-104 | 年龄与身份声明 | P0 | 注册时声明出生年份；未满 16 岁阻止注册并提示；年龄信息仅用于合规与常模分层，不公开展示 |
| FR-105 | 账号注销与删除 | P0 | 应用内可发起；二次确认并说明后果；15 个工作日内完成删除或匿名化；邮件/站内信告知结果；法定留存数据单独说明 |
| FR-106 | 多端同步 | P1 | 同一账号在不同设备看到一致的报告与历史；冲突以服务端版本为准；同步失败可重试且不重复计分 |
| FR-107 | 授权管理 | P1 | 用户可查看并撤回研究、营销、第三方共享授权；撤回后停止后续处理，不影响此前已完成的合法处理 |

**FR-102 补充规则**：

- 密码长度 ≥ 10，禁止常见弱密码；服务端使用 Argon2id/bcrypt 存储；
- 验证码发送频控：同一手机号 60 秒 1 次、每日 ≤ 10 次；防撞库与枚举；
- 登录、改密、注销等敏感操作需二次验证。

### 5.2 测评与任务（FR-200）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-201 | 测评目录与详情 | P0 | 展示名称、目的、维度、预计时长、题目数量、适用人群、局限与免责声明；未登录可查看 |
| FR-202 | 知情同意 | P0 | 用可读语言说明数据用途、保存期限、自愿参与、退出方式、风险与联系方式；必须主动勾选（默认不勾选）方可开始；记录同意版本、时间与用户标识 |
| FR-203 | 测评前环境检查 | P0 | 检查浏览器/设备、网络、屏幕、音量（如需要）、全屏与输入；不通过时给出可操作建议；允许在知情风险下跳过并记录 |
| FR-204 | 测评运行 | P0 | 单题单屏、进度可见；按题型计时/限时；每次作答即时保存；输入延迟目标 ≤100ms；异常退出不丢已答 |
| FR-205 | 中断与恢复 | P0 | 刷新/断网/切换设备后可在【待定：24 小时】内恢复；恢复后定位到上次题目；超时自动提交或标记放弃，规则明确 |
| FR-206 | 提交与完整性校验 | P0 | 提交前检查必答题、异常快答、重复提交；用户确认后提交；提交幂等，重复请求不产生第二份结果；展示提交成功回执 |
| FR-207 | 防作弊与异常检测 | P1 | 记录切屏、复制粘贴、多开、异常速度等信号；达到阈值标记低可信而非直接封禁；用户可申诉；规则不公开细节以防规避 |
| FR-208 | 自适应调度（CAT） | P1 | v1.1 启用；按能力估计选题，控制题目曝光与内容平衡；同一版本可复现；无合适题库时回退固定题本 |
| FR-209 | 无障碍作答 | P1 | 键盘可完成；屏幕阅读器可读题与选项；允许延长时限/暂停（需记录，可能影响常模解释）；提供减少动效 |
| FR-210 | 多语言 | P2 | 架构支持 i18n；首版仅 zh-CN；翻译不影响计分版本 |

**FR-204 计时规则（待确认）**：

- 认知任务类：按任务范式固定刺激时长与反应窗口，超时记为缺失/错误，规则需在算法文档中定义；
- 自评量表类：不强制单题限时，但记录总时长用于效度参考；
- 用户主动暂停仅限允许的题型，暂停次数与时长记录并在报告中提示。

### 5.3 计分与报告（FR-300）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-301 | 自动计分 | P0 | 提交后自动触发；结果 ≤【待定：10 秒】返回；同输入同版本结果一致；计分版本随会话固定，不受后续配置变更影响 |
| FR-302 | 效度校验 | P0 | 至少覆盖作答一致性、反应时异常、缺失/随机作答；输出可信等级与原因；低可信时不展示确定性结论 |
| FR-303 | 常模与百分位 | P0 | 按适用分层计算百分位与置信区间；无可用常模时展示原始分并明确说明；常模版本可追溯 |
| FR-304 | 多维画像 | P0 | 每个维度展示分数/百分位、描述性区间与一句话解释；不使用「好/坏/正常/异常」等诊断化标签；移动端可读 |
| FR-305 | 报告生成 | P0 | 报告包含：摘要、维度、可信度、解释、建议、局限、免责声明、求助资源；首屏 10 秒内可理解核心结论；支持重新生成（同版本） |
| FR-306 | 解释与行动建议 | P0 | 建议 3–5 条，具体、可执行、可验证；与维度结果对应；不提供药物、治疗或诊断建议；标注证据强度与不确定性 |
| FR-307 | 安全提示与危机资源 | P0 | 涉及自伤/自杀相关题目或关键词时，展示求助热线与紧急资源；说明产品不能提供危机干预；不因此自动标记用户为高风险或对外共享 |
| FR-308 | 报告版本与重算 | P1 | 旧报告不可原地篡改；重算生成新版本并标注差异；用户可查看历史版本 |
| FR-309 | 报告导出 | P1 | 支持 PDF【待定】；导出需登录与二次确认；文件含水印/报告编号；下载链接有有效期 |
| FR-310 | AI 辅助解读 | P2 | 若启用，需明确标注 AI 生成、可关闭、不替代专业意见；输入脱敏；输出经安全过滤与人工抽检 |

**FR-305 报告结构（建议顺序）**：

1. 一句话结论 + 可信度徽标；
2. 多维画像图与维度卡片；
3. 结果解释（含「这意味着什么/不意味着什么」）；
4. 3–5 条行动建议；
5. 局限与下次复测建议；
6. 免责声明与求助资源；
7. 分享/导出/删除入口。

**FR-307 安全规则**：

- 危机资源文案需由心理测量顾问与法务审核；
- 热线号码与地区必须可配置、可更新；
- 不做风险分级推送，不将危机信号用于营销；
- 相关事件单独审计，限制访问。

### 5.4 追踪与成长（FR-400）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-401 | 历史记录 | P0 | 按时间倒序列出测评；展示日期、版本、可信度、主要维度；支持分页与单条删除；删除后不可恢复（法定留存除外） |
| FR-402 | 趋势对比 | P1 | 选择 2 次及以上测评生成趋势；仅比较同维度、可比的版本；展示变化方向与置信区间；明确「变化不等于因果」 |
| FR-403 | 复测提醒 | P1 | 默认关闭，用户主动开启；建议间隔 ≥【待定：14 天】；频率上限【待定】；每封提醒含退订 |
| FR-404 | 个性化建议/训练计划 | P1 | 基于结果生成 2–4 周计划；任务可完成、可跳过、可调整；不承诺疗效；完成情况可追踪 |
| FR-405 | 目标与打卡 | P2 | 用户可设定小目标并记录；数据仅本人可见；可一键关闭 |
| FR-406 | 阶段总结 | P2 | 每【待定：4 次测评/季度】生成总结；可分享（脱敏）；可关闭 |

### 5.5 分享与隐私（FR-500）

| --- | --- | --- | --- |

### 5.6 运营后台（FR-600）

| ID | 需求 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| FR-601 | 题库与量表管理 | P0 | 支持题目/选项/计分键/版本的新增、预览、发布、下架、回滚；发布需双人复核；已发布版本不可直接编辑 |
| FR-602 | 计分与常模版本 | P0 | 配置计分规则、常模与报告模板；变更需审批与审计；支持灰度与回滚；旧会话使用旧版本 |
| FR-603 | 内容管理 | P1 | 管理科普文章、报告片段、免责声明与危机资源；支持定时发布与版本记录 |
| FR-604 | 运营看板 | P1 | 展示漏斗、完成率、效度异常率、留存、付费等聚合指标；默认脱敏，禁止下钻到个体（授权例外需审计） |
| FR-605 | 客服工单 | P2 | 查看用户同意记录与请求状态；不可见完整作答；操作留痕 |
| FR-606 | 实验与灰度 | P1 | 支持功能开关、A/B 分流与白名单；实验不得绕过知情同意或隐私设置 |
| FR-607 | 审计日志 | P0 | 记录管理员登录、配置变更、数据访问/导出、权限变更；保留 ≥180 天；日志不可被普通管理员删除 |

**后台通用规则**：

- 最小权限与职责分离：内容发布与计分配置不能由同一人独立完成；
- 敏感操作二次确认 + 原因填写；
- 批量导出需审批，导出文件加密并设置有效期；
- 所有后台页面禁止被搜索引擎索引。

## 8. 接口需求

### 8.1 通用约定

- 风格：REST + JSON，路径版本 `/api/v1`；
- 认证：Bearer JWT（短期 access + 可轮换 refresh）；匿名会话使用受限 token；
- 时间：ISO 8601 UTC；数据库存 UTC，展示按用户时区；
- 幂等：提交、支付、删除等使用 `Idempotency-Key`；
- 错误：统一 `code/message/trace_id`，不泄露内部堆栈；
- 分页：cursor 优先；默认 20，最大 100；
- 限流：按用户/IP/接口分级，返回 `429` 与重试提示；
- 审计：敏感接口记录 actor、对象、结果与理由。

## 10. 测评会话状态机

| 状态 | 说明 | 允许的下一状态 |
| --- | --- | --- |
| `CREATED` | 已创建，未同意 | `CONSENTED`、`EXPIRED` |
| `CONSENTED` | 已同意，未开始 | `IN_PROGRESS`、`ABANDONED` |
| `IN_PROGRESS` | 作答中 | `SUBMITTED`、`ABANDONED`、`EXPIRED` |
| `SUBMITTED` | 已提交，待计分 | `SCORING`、`FAILED` |
| `SCORING` | 计分中 | `SCORED`、`FAILED` |
| `SCORED` | 计分完成 | `REPORTED` |
| `REPORTED` | 报告可用 | 终态（可重算生成新版本） |
| `INVALID` | 效度过低/数据异常 | 终态；可引导重测 |
| `ABANDONED` | 用户放弃 | 终态 |
| `EXPIRED` | 超时未完成 | 终态 |
| `FAILED` | 计分失败 | 可重试回 `SCORING` |

规则：

- 状态迁移必须原子化并记录时间、触发者与版本；
- 提交幂等：同一会话重复提交返回同一 `report_id`；
- 计分失败不得丢失作答；重试使用相同计分版本；
- 任何终态都可被用户删除，但审计日志按规则保留。

## 12. 验收与发布标准

### 12.1 功能验收

- P0 需求全部实现并通过验收用例；
- P1 未完成项有明确排期且不影响核心旅程；
- 关键路径（首次测评、断点续答、报告、注销）端到端通过；
- 异常路径（断网、超时、重复提交、支付失败、权限不足）有明确提示且可恢复。

### 12.2 发布门禁

| 门禁 | 标准 | 证据 |
| --- | --- | --- |
| 功能 | P0 全通过，无 S1/S2 缺陷 | 测试报告 |
| 性能 | 达到 NFR-PERF 门槛 | 压测报告 |
| 安全 | 无高危漏洞，渗透测试通过 | 安全报告 |
| 隐私 | 同意、导出、删除、保留期可演示 | 合规检查表 |
| 无障碍 | 关键路径 WCAG 2.1 AA | axe + 人工检查 |
| 科学性 | 量表授权、计分与文案经顾问签字 | 评审记录 |
| 运营 | 监控、告警、回滚、客服手册就绪 | 发布清单 |

### 12.3 需求验收格式

每条需求至少有一个用例，采用 Given/When/Then 描述；示例（FR-205）：

```gherkin
Given 用户正在进行测评且已作答 10 题
When 用户刷新页面或断网后重新进入
Then 系统恢复到第 10 题并保留此前作答
And 恢复时间不超过 2 秒
And 若超过 24 小时，提示会话已过期并说明是否可重测
```
