## 二、背景与问题

年轻人想了解自己的能力结构，通常只有两条路：

- 做娱乐化测试或脑力小游戏：传播强，但结果不可信、不可复测；
- 去医院或专业机构：准确，但贵、慢、门槛高。

即使做出一个可用的测评，用户仍会遇到第二个问题：**分数看完了，然后呢？**

- 不知道这个分数意味着什么；
- 不知道先练什么、怎么练；
- 下次复测时，不记得上次说过什么；
- 换设备、换时间，历史断裂。

MindMeter 的机会不是再做一个“打分器”，而是做一个**能记住你、能解释、能陪你在多次测评之间做决定的 Agent**。

**问题陈述**：18–30 岁的大学生和职场新人，缺少一个能长期记住自己能力结构、解释变化、给出可执行建议的对话式能力顾问。

## 三、5W1H

| 维度 | 回答 |
| --- | --- |
| Why | 测评只给分数，不给解释和下一步；单次结果无法形成长期监测；通用聊天 AI 没有用户的测评 facts |
| What | 一个“八维能力测评 + 对话式 Agent”的 Web 产品：测评产生 facts，Agent 结合记忆与知识库做解释、建议、追问和趋势分析 |
| Who | 18–30 岁大学生、职场新人；项目组 4 人；后续可扩展到职业咨询/学习教练场景 |
| When | 不设课程 deadline；按 M0–M3 分阶段，课程结束后继续维护 |
| Where | Web 端，移动优先；账号跨设备；服务端存测评、记忆、摘要；模型由用户 BYOK |
| How | FastAPI + PostgreSQL/pgvector + LangGraph + 原生前端；服务端计分；RAG 检索知识库；校验与模板兜底 |

## 四、使命与口号

**使命**：让每个人不仅看清自己的能力结构，还能在接下来的几个月里，有一个记得自己、能解释变化、能一起做决定的 Agent。

**口号**：**玩一局，看清你的大脑；聊一次，知道下一步。**

## 五、目标用户与场景

### 5.1 目标用户

| 层级 | 人群 | 说明 |
| --- | --- | --- |
| 核心 | 18–30 岁大学生、职场新人 | 有自我提升动机，接受对话式产品 |
| 扩展 | 25–40 岁白领 | 效率焦虑、脑力疲劳，需要长期跟踪 |
| 高价值 | 备考/求职/转岗人群 | 有明确目标和时间窗口，适合 Agent 做情境化建议 |
| 暂不做 | 临床患者、未成年人、B 端企业 | 需要医疗资质、监护人流程或销售体系 |

### 5.2 核心场景

1. **首次测评后**：用户拿到八维报告，Agent 用对话解释“你是什么结构、先练什么”。
2. **追问**：用户问“为什么我联想记忆低”“这个分数准吗”“我该先练哪项”。
3. **长期跟踪**：用户 7 天后复测，Agent 比较共同维度，解释变化，提醒练习效应。
4. **情境化建议**：用户说“最近在备考”，Agent 结合记忆调整建议顺序。
5. **边界场景**：用户问诊断/用药/疾病，Agent 拒答并给替代路径；危机关键词给固定资源。

| | 有利 | 不利 |

## 七、产品定义

### 7.1 产品结构

```text
测评（8 项 / 三档）
  → facts（八维分数、完成度、历史差值）
  → Agent（解释 / 建议 / 追问 / 趋势）
  → 记忆（profile / summaries / advice / 最近 20 条）
  → 知识库（测量 / 任务 / 建议 / 边界 / 安全）
  → 长期监测（复测、共同维度趋势）
```

### 7.2 测评

- 8 项：言语理解、言语流畅性、数字运算、知觉速度、归纳推理、空间视觉化、联想记忆、自然探索；
- 三档：快测 2 项 ≈5 分钟、标准 4 项 ≈13 分钟、深度 8 项 ≈28 分钟；
- 0–100 参考分；**不设总分、没有常模、不做百分位/误差范围**；
- 服务端计分；报告标注“课程/产品演示参考分，非常模、非临床、无人群比较”。

### 7.3 Agent

- 解释八维结果、给 2–3 条建议、回答追问、解释复测趋势；
- 不做 7 天计划/打卡、不做情绪支持/心理疏导、不做诊断/用药建议；
- 必须引用 facts / 记忆 / 知识库；数字不得编造；
- 默认模板兜底；模型不可用时报告仍完整。

### 7.4 记忆与长期监测

- 短期：最近 20 条消息；
- 长期：用户画像（目标/偏好/约束）、每次测评摘要、接受/拒绝的建议；
- 趋势：只比较共同维度；至少 3 次、间隔 7 天以上才有趋势可讲；
- 不主动推送（M1）；应用内复测提示；
- 用户可查看/编辑/删除/导出记忆。

### 7.5 数据与隐私

- 账号：邮箱 + 密码；18+；不收集姓名/手机号/学校/公司/年龄/学历；
- 服务端存测评、记忆、摘要、最近 20 条对话；不存原始音频/转写全文；
- BYOK：用户模型 Key 加密存库，主密钥只放环境变量；
- 保留期：账号存续期；删除账号后 30 天内清除；
- 支持导出/删除；AI 请求只发维度分、facts、记忆摘要、知识块，不发身份信息。

## 八、路线图（无固定 deadline）

| 阶段 | 目标 | 验收 |
| --- | --- | --- |
| M0 设计 | 领域模型、API、数据模型、隐私、知识库 schema、评测集 | 接口/模型定稿 |
| M1 纵向切片 | 账号 + 标准 4 项 + 服务端计分 + 对话 + 记忆 + RAG + 趋势 | 一个用户能“测→聊→记住→复测→解释变化” |
| M2 完整测评 | 快测/深度、8 项、ASR、三档、4 款练习（P2） | 8 项跑通 |
| M3 产品化 | 评测、日志、限流、部署、备份、删除/导出、成本 | 可公开演示、可维护 |

> 先做 M1，是因为 Agent 依赖的 facts/记忆/RAG 链路比“再补 4 个任务”更决定产品成败。

## 九、成功标准

- M1：10 名用户完成“测评→对话→7 天后复测”；至少 7 人能说出 Agent 给的下一条行动；
- Agent 评测：30 条用例，准确/有依据/有用/无越界各 ≥4/5；禁用词 0；幻觉数字 0；
- RAG：retrieval hit@3 ≥80%；回答引用来源 ≥90%；
- 长期：至少 3 次测评的用户能看到共同维度趋势；报告不把变化解释为训练效果；
- 隐私：删除账号后 30 天内数据清除；导出包含测评/记忆/建议；
- 运行：API p95 ≤500ms（非 AI）；AI 首字 ≤3s（流式）或完整 ≤30s；无阻断故障。

## 十、边界与非目标

- 不做临床诊断、治疗、药物建议、危机干预替代；
- 不做常模、百分位、智商、脑龄、总分；
- 不做 7 天计划/打卡、情绪支持/心理疏导；
- 不做 B 端、付费订阅（M1–M3 不做）；
- 不做原生 App、多语言；
- 不做全自动多 Agent 自治；LangGraph 只做可控编排；
- 不把对话原文长期保存；只留最近 20 条 + 摘要。
