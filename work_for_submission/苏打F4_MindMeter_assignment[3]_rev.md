# MindMeter 沟通管理与风险管理计划

> **课程提交版（2026-10-24）历史快照。** 当前产品已演进为 L2（账号 + 服务端 Agent + 记忆 + RAG + 服务端计分），见 [docs/README.md](../docs/README.md) 与 [docs/mgmt](../docs/mgmt/)。本文不代表当前实现。

> 项目：MindMeter（心智镜）｜团队：4 人｜周期：6 周｜当前口径：8 项能力 / 三档 / 不设总分 / 无账号 / BYOK AI

## 一、沟通管理计划

说明：按生命周期组织；频度用“即时/每天/每周/里程碑”表示；产出物优先落到仓库文档、Issue、代码或可演示版本。

| 沟通内容 | 沟通频度 | 沟通方式 | 产出物 |
| --- | --- | --- | --- |
| 课程要求、评分标准与提交节点确认 | 即时/一次性 | 面对面 + 微信群 | 需求清单、提交检查表 |
| 8 项能力、三档规则与指标定义 | 每周 | 周会 + 文档评审 | 需求文档、任务规则表 |
| 竞品对比与差异化确认 | 一次性 | 文档 + 群讨论 | 竞品对比表、定位陈述 |
| 6 周计划、任务拆分与分工 | 一次性 + 每周更新 | 周会 + GitHub Issues | 里程碑计划、任务清单 |
| 原型与页面流程评审 | 每周 | 视频会议 + 原型链接 | 原型、评审意见 |
| 技术选型、目录结构与数据格式 | 一次性 | 技术评审 + 文档 | 技术方案、数据 schema |
| 8 项素材/题库与授权 | 每周 | 群 + 共享文档 | 素材清单、授权记录 |
| 视觉规范、报告模板与文案 | 每周 | 微信群 + 共享文档 | 设计稿、文案定稿 |
| 每日进度、今日任务与阻塞 | 每天 | 微信群文字 | 三行站会记录、阻塞清单 |
| 计分逻辑、任务参数与 ASR/BYOK | 每天/按需 | 语音会议 + Issue | 联调记录、计分/接入说明 |
| 代码评审与合并 | 每次 PR | GitHub Pull Request | 评审意见、合并记录 |
| 需求变更/砍功能 | 即时 | 微信群 + Issue | 变更记录、更新后的任务 |
| 测试计划、用例与验收标准 | 每两周/里程碑 | 文档 + 评审会 | 测试用例、验收清单 |
| 缺陷跟踪与修复 | 每天 | GitHub Issues | 缺陷列表、修复记录 |
| 用户测试与反馈收集 | 每周/按计划 | 线上测试 + 访谈 | 用户测试报告 |
| 上线部署与演示彩排 | 即时（发布前） | 群 + 视频会议 | 上线清单、演示脚本、备用视频 |
| 答辩材料与课程提交 | 即时（发布阶段） | 线下/视频会议 | 答辩 PPT、演示视频、文档包 |
| 线上问题与版本回滚 | 即时 | 微信群 + Issue | 处理记录、回滚记录 |
| 数据清除/隐私相关请求 | 即时 | 微信群 + 文档 | 处理记录 |
| 项目复盘与经验总结 | 即时（项目结束） | 线下会议 | 复盘记录、改进项 |

**沟通注意事项**：

- 周会不超过 30 分钟，必须产出“谁、做什么、什么时候完成”；
- 重要结论 24 小时内回写 `docs/` 或 GitHub Issue，聊天记录不作为最终依据；
- 新增功能或延期必须 4 人确认，不能两个人私下改范围；
- 8 维/三档是 2026-10-24 的拍板口径；回退到 4/7 维、总分、常模、账号后端必须重新走 4 人确认；
- 答辩前 3 天冻结功能，只修 bug；
- 最终交付：线上链接、演示视频、当前文档集、README 启动说明，不是固定的“5 份文档”。

## 二、风险管理计划

说明：只跟踪会影响 6 周交付的风险；影响程度用“高/中/低”，优先权用“高/中/低”，跟踪频率用“即时/每天/每周/每月”。

| 风险名称 | 所属维度 | 风险说明 | 影响程度 | 对工作量影响 | 对进度/成本影响 | 优先权 | 跟踪频率 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 8 项/三档范围过大 | 项目管理 | 8 个任务 + 三档 + AI/ASR，6 周做不完，最后核心缺失 | 高 | 高 | 高 | 高 | 每周 |
| 进度延期 | 进度 | 某个任务或报告卡住，W3/W4 里程碑延迟 | 高 | 高 | 高 | 高 | 每周/每天 |
| 8 维/自然探索被质疑 | 技术 | 8 项不是公认框架；自然探索来自多元智能，容易被质疑“伪科学” | 高 | 中 | 中 | 高 | 每周 |
| 素材/题库不足 | 技术 | 8 项任务需要新题库/图片；自然探索图片授权不明 | 高 | 高 | 高 | 高 | 每周 |
| 任务太长/太难 | 技术 | 深度 28 分钟、题量偏大，用户中途退出 | 高 | 中 | 中 | 高 | 每周 |
| 刷新/误关丢数据 | 技术 | 只存内存或写入失败，刷新后结果丢失 | 中 | 中 | 中 | 中 | 每天（测试期） |
| 手机/浏览器兼容 | 技术 | 小屏幕布局错位；ASR 仅 Chrome/Edge | 中 | 中 | 中 | 中 | 每周 |
| 分工不清/互相等待 | 资源 | 任务没有唯一负责人，接口对不上 | 中 | 中 | 中 | 中 | 每周 |
| 成员时间投入不足 | 资源 | 课程/实习冲突导致连续缺勤，关键模块无人接手 | 高 | 高 | 高 | 高 | 每周 |
| 答辩现场故障 | 外部 | 网络、设备或部署平台故障 | 高 | 低 | 高 | 高 | 发布前即时 |
| ASR/BYOK 不稳定 | 技术 | 识别失败、模型超时、endpoint 不支持 CORS | 中 | 中 | 中 | 中 | 每周 |
| 隐私/伦理表述不当 | 项目管理 | 文案出现“诊断/治疗/提升智商/常模”，或收集了不必要的身份信息 | 高 | 低 | 中 | 高 | 每周 |

**重点风险应对**：

1. **范围过大**：W1 写死 8 项/三档；先保快测 2 项 + 标准 4 项；深度档 W4 再决定；新增功能先删一个旧功能；不偷偷改回 4 维/总分/常模。
2. **进度延期**：每周五必须演示可运行版本；W5 留缓冲；W6 冻结功能只修 bug；延期时优先保测评和报告，砍分享、练习美化、深度档。
3. **科学性被质疑**：统一叫“多维能力画像/课程演示”，不叫智商/临床测评；8 项是产品口径；不设总分、不做百分位；公式和阈值可查；不伪造信效度。
4. **素材/题库不足**：W2 结束前每项至少一个最小题库；自然探索图片必须可授权；不够就减题量并在报告中说明。
5. **ASR/BYOK 不稳定**：ASR 失败记“未测”；AI 8 秒超时回退模板；endpoint 不支持 CORS 时提示；答辩准备断网开关。
6. **答辩故障**：准备线上版 + 本地版 + 录屏视频 + 手机热点；提前 30 分钟到场；演示只走稳定路径。

## 三、风险跟踪机制

- 每周一例会花 10 分钟过一遍风险表：有没有新风险、等级是否变化、应对是否完成；
- 每周五演示后更新状态：开放 / 缓解中 / 已关闭；
- 出现以下情况立即升级：里程碑延迟超过 1 天、核心成员连续 2 天无法投入、线上演示环境不可用、出现隐私/伦理问题；
- 风险关闭后保留记录，答辩时可说明“识别过、处理过”。
