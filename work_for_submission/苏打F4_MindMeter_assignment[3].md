# MindMeter 沟通管理与风险管理计划

> 课程提交版（2026-11-28 修订，对齐当前 L2 实现：Web 应用 + 账号 + 服务端 Agent + 记忆 + RAG + 服务端计分）。
> 产品与需求细节见 [docs/README.md](../docs/README.md) 与 [docs/mgmt](../docs/mgmt/)。

> 项目：MindMeter（心智镜）｜团队：4 人｜周期：6 周｜当前口径：8 项能力 / 三档 6–18 分钟 / 不设总分 / 账号 + 服务端 Agent（站点统一模型）

## 一、沟通管理计划

说明：按生命周期组织；频度用“即时/每天/每周/里程碑”表示；产出物优先落到仓库文档、Issue、代码或可演示版本。

| 沟通内容 | 沟通频度 | 沟通方式 | 产出物 |
| --- | --- | --- | --- |
| 课程要求、评分标准与提交节点确认 | 即时/一次性 | 面对面 + 微信群 | 需求清单、提交检查表 |
| 8 项能力、三档规则与指标定义 | 每周 | 周会 + 文档评审 | 需求文档、任务规则表 |

| 6 周计划、任务拆分与分工 | 一次性 + 每周更新 | 周会 + GitHub Issues | 里程碑计划、任务清单 |
| 原型与页面流程评审 | 每周 | 视频会议 + 原型链接 | 原型、评审意见 |

| 缺陷跟踪与修复 | 每天 | GitHub Issues | 缺陷列表、修复记录 |
| **用户反馈、投诉与合规问题** | 即时 | 群 + Issue | 处理记录、口径更新 |
| 用户测试与反馈收集 | 每周/按计划 | 线上测试 + 访谈 | 用户测试报告 |
| 上线部署与演示彩排 | 即时（发布前） | 群 + 视频会议 | 上线清单、演示脚本、备用视频 |
| 答辩材料与课程提交 | 即时（发布阶段） | 线下/视频会议 | 答辩 PPT、演示视频、文档包 |
| 线上问题与版本回滚 | 即时 | 微信群 + Issue | 处理记录、回滚记录 |
| 数据清除/隐私相关请求 | 即时 | 微信群 + 文档 | 处理记录 |
| 项目复盘与经验总结 | 即时（项目结束） | 线下会议 | 复盘记录、改进项 |

**沟通注意事项**：

- 周会不超过 30 分钟，必须产出“谁、做什么、什么时候完成”；
- 重要结论 24 小时内回写 `docs/` 或 GitHub Issue，聊天记录不作为最终依据；
- 新增功能或延期必须 4 人确认，不能两个人私下改范围；
- 8 维/三档是 2026-10-24 的拍板口径；回退到 4/7 维、总分、常模必须重新走 4 人确认；
- 对外内容（社媒、演示、宣传）发布前必须过“非诊断/无常模/18+”检查清单；
- 答辩前 3 天冻结功能，只修 bug；
- 最终交付：线上链接、演示视频、当前文档集、README 启动说明。

## 二、风险管理计划

说明：只跟踪**可能发生、且一旦发生会影响交付**的不确定事件；概率用“高/中/低”，并给每个风险一个可观察的触发信号，避免“写了但没人看”。

| 风险名称 | 维度 | 不确定事件 | 概率 | 影响 | 优先权 | 触发信号 | 应对要点 | 跟踪频率 |
| --- | --- | --- | :---: | :---: | :---: | --- | --- | --- |
| 模型输出越界或幻觉 | 技术 | 模型升级或提示词漂移，出现临床化措辞、编造数字 | 中 | 高 | 高 | 校验失败率上升、抽查发现禁用词 | 数字白名单 + 禁词 + 引用 + 模板兜底；每周抽 20 条复核 | 每周 |
| 第三方模型服务不可用/涨价 | 外部 | 限流、超时、涨价或下线 | 中 | 高 | 高 | 429/超时率上升、账单异常 | 备用模型与模板兜底；成本告警 | 每周/即时 |
| 云服务器故障或版本滞后 | 外部 | 机器故障、证书过期；只 pull 不重建导致旧界面 | 中 | 高 | 高 | 健康检查失败、页面版本不符 | 备份、部署脚本（pull→rebuild→重启）、健康检查 | 每周 |
| 获客效果不确定 | 市场 | 平台限流或审核，注册→完测转化低于预期 | 高 | 中 | 高 | 曝光高但注册低、完测率 <30% | 多平台备选（公众号/知乎）、内容 A/B、漏斗看板 | 每周 |
| 心理测评内容合规 | 合规 | 平台或监管把内容误读为诊断/医疗建议 | 中 | 高 | 高 | 平台下架、审核驳回、用户投诉 | 非诊断口径、18+、文案审阅、避免敏感词 | 每周 |
| 数据隐私与账号安全 | 安全 | 密码泄露、会话劫持、导出泄露 | 低 | 高 | 高 | 异常登录、导出频率异常 | HttpOnly/SameSite、限流、脱敏、最小化收集 | 每周 |
| 复测留存不足 | 产品 | 首测后不再回来，趋势与记忆功能失效 | 中 | 中 | 中 | 7 日复测率 <10% | 复测提醒、趋势解读、练习入口 | 每周 |
| 团队投入不足 | 资源 | 课程/实习冲突，关键模块无人接手 | 中 | 高 | 高 | 连续 2 天无产出、里程碑延迟 | 任务看板、备份负责人、每周五演示 | 每周 |
| 答辩现场网络/设备 | 外部 | 断网、投影或浏览器异常 | 中 | 高 | 高 | 彩排失败 | 本地备份 + 录屏 + 手机热点 | 发布前 |
| 计分口径变更导致历史不可比 | 技术 | 版本升级（如 v3.2→v3.3）后分数不可比 | 中 | 中 | 中 | 版本号变更 | 版本标注、不重算历史、趋势说明 | 每版本 |

**重点风险应对**：

1. **模型越界**：三道闸——数字白名单（只允许 facts 及确定性派生）、禁词与边界句校验、硬校验失败即回退场景模板；每周抽 20 条对话复核，问题沉淀进评测集。
2. **模型服务不可用**：备用模型 + 超时降级 + 模板兜底；监控调用量与成本，涨价超过阈值再评估新供应商。
3. **获客不确定**：先小样本验证内容方向；小红书/B 站/抖音各自设定可关停的试验，用「注册→完测→7 日复测」漏斗判断；不达标先改内容与落地页，不盲目加投放。
4. **合规**：对外文案统一过“非诊断/无常模/18+”清单；社媒避免“诊断/治疗/测试心理疾病”等表述；被平台驳回时立即下架改写，并同步更新口径。
5. **数据安全**：账号最小化收集、登录限流、日志脱敏、导出不含密钥；模型 Key 只在服务端环境变量，定期轮换。
6. **部署滞后**：把「pull → rebuild → 重启容器」固化进部署文档与脚本；上线后冒烟核对版本号与页面标记。
7. **留存不足**：把复测提醒与趋势解释做成产品能力；用真实用户测试验证「隔周再测」的意愿，不达标时先优化报告可读性。

## 三、风险跟踪机制

- 每周一例会花 10 分钟过一遍风险表：有没有新风险、概率/影响是否变化、触发信号是否出现；
- 每周五演示后更新状态：开放 / 缓解中 / 已关闭；
- 出现以下情况立即升级：里程碑延迟超过 1 天、核心成员连续 2 天无法投入、线上演示环境不可用、出现隐私/合规问题、模型越界被用户投诉；
- 风险关闭后保留记录，答辩时可说明“识别过、处理过”。
